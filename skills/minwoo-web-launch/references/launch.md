# 사이트에 맞는 출시 기준

- 경로: 첫 화면뿐 아니라 주요 상세 경로를 주소로 직접 열고 새로고침한다. 없는 경로의 상태·화면과 SPA fallback이 실제 404를 숨기는지 확인한다.
- 링크: 내부 링크·페이지 내 앵커·외부 링크를 구분한다. 전체 사이트를 무제한 순회하지 말고 승인된 경로부터 확인한다. 로그아웃·삭제 같은 동작 URL은 자동 방문하지 않는다. 외부 링크 미검사를 통과로 기록하지 않는다.
- 공유: title·설명·대표 이미지와 URL을 확인한다. 메타데이터 존재, 이미지의 실제 접근, 특정 서비스의 공유 캐시 갱신은 서로 다른 검증이다.
- 폼: 성공 문구만 확인하지 말고 테스트 환경의 저장·접수 증거까지 연결한다. 실제 메일·문자·결제는 이미 허용된 범위에서만 실행한다. 미리보기에서 대신한 시험을 운영 실전으로 표현하지 않는다.
- 공개 의도: 테스트용 noindex·인증 보호를 무조건 제거하지 않는다. 공개할 페이지와 비공개 페이지를 먼저 구분한다.
- 운영: 배포 커밋, 설정 키의 존재(비밀값 제외), 공개 주소, 복구 절차와 담당 경로를 확인한다. 롤백 문서 검토를 실제 롤백 시험으로 표현하지 않는다.
- 연결: Vercel을 선택한 프로젝트에서만 해당 도구를 검토한다. Sites·다른 호스팅을 임의로 교체하지 않는다. PostHog 등 운영 분석은 측정 목적·수집 대상·환경이 정해졌을 때 별도로 연결하며 스킬 설치가 추적 코드를 자동 삽입하지 않는다.

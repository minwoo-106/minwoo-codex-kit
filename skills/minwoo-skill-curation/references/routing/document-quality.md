# 문서 편집·디자인 검수

보고서·일지·안내문을 새로 만들거나 서식을 개편할 때 적용한다. 독자가 업무에 바로 쓸 수 있는 문서가 목적이다. ‘AI처럼 보임’은 작성 주체를 판별하는 검사가 아니며, 아래 기준으로 인간 작성이나 취향 일치를 보장하지 않는다.

## 양식과 역할부터 고정

- 사용자 지정 양식·참고 문서·필수 항목을 시각 설계의 기준으로 삼는다. 그 범위 안에서 문서 용도와 독자에 맞춰 결정하고, 일반 디자인 취향은 마지막 기본값으로만 쓴다. 정해진 서식의 로고·결재란·머리말·쪽번호·필수 고지를 ‘장식’이라고 임의 삭제하지 않는다.
- 양식이 없으면 요청에서 알 수 있는 독자·용도에 맞춰 시작한다. 내부 주간 기록은 제목·기간·업무 내용·다음 조치 등 필요한 정보로 충분할 수 있다. 표지·요약 카드·부제·슬로건을 기본 세트로 추가하지 않는다. 이미 충분한 정보가 있는데 양식 선택이나 단계별 승인을 새로 요구하지 않는다.
- Word/PDF 등 현재 형식의 필수 제작·템플릿 선택·렌더 검증 절차는 해당 스킬이 맡는다. 이 문서는 제작기를 교체하거나 필수 절차를 생략하는 권한이 아니다. 문체 수정이 필요할 때만 minwoo-natural-writing을 보조로 사용한다. 웹 UI의 카드·히어로·대시보드 문법을 일반 업무 문서에 자동 적용하지 않는다.

## 각 요소의 용도 확인

- 작은 머리말, 반복되는 문서명, 요약 상자, 색 띠, 항목마다 붙은 굵은 문구는 각각 독자가 찾거나 판단할 정보를 돕는지 본다. 내용과 역할이 중복되면 통합한다. 작은 글씨·색·굵게·표·각주 자체를 금지하지 않는다.
- 편집 과정 설명, ‘이 문서는 … 정리했습니다’ 같은 불필요한 자기 설명, 사용자에게 할 작업 완료 안내는 제출 문서에서 분리한다. 문서에 필요한 작성 기준·근거·책임 범위는 남긴다.
- 불확실성·출처·조건을 보기 좋게 만들려고 삭제하지 않는다. 예를 들어 계획일이 확정 일정이 아니라면 표 열을 ‘내부 목표일’로 명확히 하고 필요한 조건을 해당 표 바로 옆에서 읽을 수 있게 한다. 별도 의무 고지라면 원문·위치를 보존한다.
- 숫자·날짜·담당·상태·부정·출처는 입력과 대조한다. ‘검토 중’을 ‘완료’로 바꾸거나 자연스러움을 위해 사실·경험·성과를 추가하지 않는다. 독자가 상태와 다음 행동을 구별할 수 있게 쓴다.

## 읽기와 페이지 구성

- 본문은 실제 출력 크기에서 편히 읽을 수 있게 한다. 일반 A4 업무 문서는 본문 10.5–12pt 정도를 출발점으로 삼되 양식·글꼴·독자를 우선한다. 필수 내용을 작은 하단 글씨로 밀어내거나 분량을 맞추려고 전체 글자를 줄이지 않는다.
- 표는 비교·상태·일정처럼 행과 열의 관계가 있을 때 쓴다. 긴 설명을 억지로 셀에 넣지 않는다. 행 분할·반복 제목·단위·줄바꿈을 실제 페이지에서 확인한다.
- 내용의 흐름으로 페이지를 나눈다. 요청되지 않은 표지나 한 주제당 한 페이지를 자동 추가하지 않는다. 긴 문서를 한 페이지로 강제로 줄이지도 않는다. 적당한 여백을 장식이나 중복 요약으로 채우지 않는다.

## 최종 검수

1. 원문과 대조해 필수 항목·사실·출처·제한 조건이 남았는지 확인한다.
2. 모든 페이지를 렌더해 전체 흐름과 실제 읽기 크기를 함께 본다. 잘림·겹침·한글 깨짐 외에 뜬금없는 작은 글씨, 의미 없는 반복, 불균형한 페이지 나눔을 점검한다.
3. 제작 과정 설명을 모르는 독자의 관점에서 ‘무슨 상태인가, 내가 무엇을 판단하거나 해야 하나, 아직 확정되지 않은 것은 무엇인가’를 찾아본다. 이 질문에 필요한 내용만 보완하고 사용자가 요청하지 않은 독자 시험·별도 에이전트·검수 보고서를 매번 만들지 않는다.
4. 사용자가 지정한 장식·양식이나 필수 고지가 남았는지 역으로 확인한다. 자연스럽게 보이려는 수정 때문에 정보가 사라졌다면 되돌린다.

이 기준은 사용자 요청 범위와 기존 승인 방식을 유지한다. 외부 전송·게시·플러그인 설치·설정 변경 권한을 추가하지 않는다. 검수 메모는 요청이 없으면 제출 문서에 끼워 넣지 않는다.

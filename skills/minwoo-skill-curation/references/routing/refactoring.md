# 동작을 보존하는 코드 정리

사용자가 정리하려는 범위와 유지할 공개 동작·입출력·오류·부작용을 고정한다. 기존 테스트가 부족하면 관찰 가능한 경계에서 현재 동작을 기록하는 테스트를 필요한 만큼 보강한다. 발견한 버그를 리팩터링에 섞어 몰래 고치지 않는다.

- 인터페이스·모듈 경계 개선이 필요하면 codebase-design을 주도로 선택한다. 작은 중복 정리에는 별도 설계 절차를 강제하지 않는다.
- 기존 테스트의 검증력이 의심될 때만 minwoo-test-quality, 불변식 생성이 유용할 때만 minwoo-property-testing을 추가한다. 테스트 우선 개발을 명시한 경우에 tdd를 사용한다.
- 작게 이동·분리하고 각 의미 있는 단계에서 관련 테스트를 실행한다. 이전/이후를 같은 입력으로 비교하며 원본을 실행 중에 덮어써 기준을 잃지 않는다.
- 외부 호출·파일 기록 순서·예외 타입·기본값도 호환성이다. 함수 길이나 줄 수 감소만으로 개선이라고 판단하지 않는다.
- 리뷰를 요청했으면 code-review로 확정 범위를 검토한다. 일반 리팩터링에 모든 리뷰·보안·성능 스킬을 붙이지 않는다.

결과에 바뀐 구조와 유지한 계약, 실제 비교 범위, 확인 못한 부분을 남긴다. 공개 API나 저장 형식이 달라지면 동작 보존 작업인지 다시 판단하고 현재 요청 범위를 따른다.

# 동작을 보존하는 코드 정리

사용자가 정리하려는 범위와 유지할 공개 동작·입출력·오류·부작용을 고정한다. 기존 테스트가 부족하면 관찰 가능한 경계에서 현재 동작을 기록하는 테스트를 필요한 만큼 보강한다. 발견한 버그를 리팩터링에 섞어 몰래 고치지 않는다.

- 인터페이스·모듈 경계 개선이 필요하면 codebase-design을 주도로 선택한다. 작은 중복 정리에는 별도 설계 절차를 강제하지 않는다.
- 기존 테스트의 검증력이 의심될 때만 minwoo-test-quality, 불변식 생성이 유용할 때만 minwoo-property-testing을 추가한다. 테스트 우선 개발을 명시한 경우에 tdd를 사용한다.
- 작게 이동·분리하고 각 의미 있는 단계에서 관련 테스트를 실행한다. 이전/이후를 같은 입력으로 비교하며 원본을 실행 중에 덮어써 기준을 잃지 않는다.
- 외부 호출·파일 기록 순서·예외 타입·기본값도 호환성이다. 함수 길이나 줄 수 감소만으로 개선이라고 판단하지 않는다.
- 리뷰를 요청했으면 code-review로 확정 범위를 검토한다. 일반 리팩터링에 모든 리뷰·보안·성능 스킬을 붙이지 않는다.

결과에 바뀐 구조와 유지한 계약, 실제 비교 범위, 확인 못한 부분을 남긴다. 공개 API나 저장 형식이 달라지면 동작 보존 작업인지 다시 판단하고 현재 요청 범위를 따른다.

## 단순화와 재사용 판단

줄 수가 아니라 같은 요구사항을 충족하는 데 필요한 개념·상태·분기·관리 부담을 줄인다. 이미 명확한 구현을 억지로 바꾸지 않는다.

1. 변경할 동작과 보존할 계약을 먼저 정한다. 미래 기능을 추측해 확장 지점을 만들지 않는다.
2. 관련 호출자에서 기존 구현·프로젝트 패턴을 찾고, 다음으로 표준 기능·설치된 의존성을 살핀다. 발견한 후보가 오류 처리·환경·접근성·성능 요구까지 충족하는지 확인한 뒤 재사용한다. 이름이 비슷하다는 이유로 서로 다른 업무 규칙을 합치지 않는다.
3. 작업 범위에서 중복 계산·불필요한 상태·분기·전달만 하는 계층을 제거할 수 있는지 확인한다. 짧은 한 줄에 복잡한 조건을 숨기거나 작은 공통 부분 때문에 여러 옵션을 가진 범용 함수를 만들지 않는다.
4. 기존 테스트와 필요한 경계 입력으로 전후 동작을 비교한다. 공개 입출력·예외·부작용을 유지하고, 보안·데이터 손실 방지·접근성 검사를 삭제해 수치를 개선하지 않는다. 더 큰 구조 변경이 필요하면 이번 범위와 분리해 설명한다.

예를 들어 날짜 선택기를 기본 위젯으로 바꾸기 전에 범위 선택·업무상 금지일·키보드 조작·지원 환경이 유지되는지 확인한다. 기본 기능으로 충족하지 못하면 필요한 맞춤 구현을 남긴다. 기존의 일관된 컴포넌트를 우회하면서까지 기본 위젯을 강제하지 않는다.

새 의존성에 구현을 숨긴 것은 복잡성의 제거와 다르다. 설치·업데이트·번들·배포 부담까지 비교한다. 실행 속도·메모리 개선은 같은 조건에서 측정했을 때만 주장한다. 작은 수정에 별도 점수표·벤치마크·승인을 강제하지 않는다.

토론 요청에는 선택지와 제약을 먼저 논의한다. 구현 요청에는 이미 허용된 범위에서 판단·구현·검증하고, 단순화를 이유로 요구사항을 임의로 축소하거나 추가 승인 단계를 만들지 않는다.

[Ponytail 검수와 비교 시험](ponytail-review.md)의 재사용 관점을 참고해 기존 안내에 통합했다. 별도 상시 스킬이나 훅은 추가하지 않는다.

## 변경 영향과 리뷰 피드백

여러 모듈·공개 인터페이스·데이터가 연결된 변경이면 실제 호출자·소비자·설정·이행 순서와 필요한 검증을 짧게 확인한다. 완료 후 계획과 실제 diff를 비교한다. 폴더 이름만으로 의존성을 추정하거나 영향 분석 때문에 새로운 문서 체계를 만들지 않는다. API 계약은 minwoo-api-compat, DB 변경은 minwoo-postgres-review, 모듈 설계는 codebase-design에 맡긴다.

리뷰 지적은 코드·버전·기존 계약·재현과 대조한 뒤 반영한다. 틀린 지적에는 기술적 근거를 설명하고, 관련 없는 정리를 함께 넣지 않는다. 일부 지적이 모호해도 독립적이고 이미 허용된 수정까지 일괄 중단하지 않는다. 의미 있는 변경 뒤 필요한 검증을 실행하고, 추가 변경이 없으면 같은 검사를 형식적으로 반복하지 않는다.

[ECC·Superpowers 검수 기록](ai-workflow-candidates.md)의 일부 관점만 연결한 독자 안내다. 외부 스킬의 문서 승인·항상 TDD·자동 작업 트리·에이전트·전체 재시험·표현 금지 규칙은 이식하지 않는다.

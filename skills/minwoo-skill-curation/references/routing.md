# 작업별 도구 선택 — Codex 진입점

여러 스킬의 역할이 겹치거나 작업을 여러 분야로 나눠야 할 때만 읽는다. 단순 답변·이미 선택이 명확한 작업에는 이 안내도 생략한다.

1. 사용자 지정 도구·파일 형식·작업 위치와 프로젝트 지침을 먼저 적용한다.
2. 아래에서 현재 단계에 해당하는 문서 하나를 읽고 주도 스킬을 고른다. 서로 다른 단계가 필요해질 때만 다음 문서를 읽는다.
3. 보조 스킬은 주도 스킬에 없는 구체적인 역할이 있을 때 추가한다. 같은 디자인 방향·동일 문서·같은 배포를 두 도구가 동시에 맡지 않는다.
4. 실제 세션의 스킬 목록·도구를 확인하고 선택한 SKILL.md와 필수 선행 문서를 읽는다. 여기의 이름은 설치·로그인·권한·실행 성공의 증거가 아니다.
5. 이용 가능한 기존 도구로 충분하면 새로 설치하지 않는다. 빠진 기능이 실제로 필요할 때만 plugin-management 또는 skill-installer로 확인한다.

## 겹침을 해결하는 기준

- 먼저 정한 결과물의 위치와 형식을 유지한다. 같은 자료의 사본을 여러 서비스에 만들지 않는다.
- UI 주도 스킬은 한 단계에 하나를 기본으로 한다. 예: 브랜드 방향은 design-taste-frontend, 기존 화면 개선은 impeccable. 21st는 구성 요소·구현, 브라우저 검사는 실제 동작이라는 별도 역할이다.
- 평가·리뷰·성능·의존성 감사를 모든 구현에 붙이지 않는다. 요청 또는 구체적인 결함·위험이 있을 때 선택한다.
- 이 문서는 선택 기본값이다. 현재 요청, 프로젝트 규칙, 플랫폼의 필수 스킬·선행 절차를 대체하지 않는다. 명시적으로 지정한 스킬은 임의로 제외하지 않는다.
- 선택은 실행 권한을 새로 주지 않는다. 기존 승인 방식과 이미 허용된 범위를 유지하고 추가 승인 절차를 만들지 않는다.
- 분류는 문서상 역할 구분이다. 폴더 이동·스킬 비활성화·플러그인 캐시 수정·자동 호출 훅을 뜻하지 않는다.

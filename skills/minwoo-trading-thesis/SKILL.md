# 자동매매 연구 가설 추적

기존 연구 결과를 근거로 가설이 강해졌는지 약해졌는지 판단한다. 원본 Thesis Tracker를 기업별 투자 논거에서 전략 실험의 가설 관리로 한국어 각색했다. 출처·변경·재배포 조건은 [UPSTREAM.md](UPSTREAM.md), 라이선스는 [LICENSE](LICENSE)에 있다.

## 기존 기록에서 시작

사용자가 지정한 가설, 고정된 후보 정의, 기존 판정 기준과 보고서를 먼저 읽는다. 기존 EOD/주간 보고서에 관련 절이 있으면 갱신하고 별도 장부나 상시 에이전트를 중복 생성하지 않는다. 읽기 전용 요청은 답변으로 끝낸다. 기록 요청일 때만 지정된 연구 문서·구조화 파일을 갱신한다.

실제 모의계좌, 동일 조건 가상 비교, 과거 재구성, 규칙 고정 후 신규 관측을 분리한다. 기간·자본·비용·체결 모델·가격 관측 범위가 다른 결과는 직접 우열의 근거로 쓰지 않는다. 손익 계산이나 Replay가 필요하면 프로젝트의 기존 분석 기능을 사용한다. `minwoo-trading-research`가 있다면 그 검증 범위를 따르되 이 스킬 사용을 위해 설치하지는 않는다.

## 가설과 반박 조건 고정

가설마다 다음을 연결한다. 기존 스키마와 식별자를 우선하며 없는 기록을 과거 사실처럼 복원하지 않는다.

- 가설 ID·버전, 최초 기록일, 대상 후보·기준선 버전.
- 기대하는 작동 원리: 어떤 변경이 어떤 문제를 어떻게 개선할 것으로 예상했는가.
- 확인할 지표와 반박 조건: 무엇이 관측되면 기대가 틀렸다고 판단할 수 있는가.
- 고정 당시 사용한 자료 범위, 검토 기한 또는 검토를 촉발할 사건.

결과를 이미 본 뒤 만든 가설은 사후 가설로 표시하고 이후 관측부터 평가한다. 손익에 맞춰 임계값·판정 기한·성공 조건을 조용히 바꾸지 않는다. 변경이 필요하면 새 버전과 이유를 남긴다. 기존 판정 기준이 없으면 검토용 제안을 구분해서 제시하고 승인된 실험 조건처럼 취급하지 않는다.

## 새 증거를 대조

각 증거에 발생 시점, 관측 가능 시점, 보고서 경로·실험 ID, 비교 대상, 자료 품질을 남긴다. 같은 거래의 일별 재보고를 새로운 독립 표본으로 중복 집계하지 않는다. 같은 가설을 여러 번 시험한 결과도 독립적인 성공 사례처럼 합치지 않는다.

- 지지·반박·혼재·판단 불가를 구분하고, 유리한 결과와 불리한 결과에 같은 자료 품질 기준을 적용한다.
- 결과가 좋아졌는지와 의도한 원리가 확인됐는지를 분리한다. 상관관계만으로 손익 변화의 원인을 확정하지 않는다.
- 완료 거래, 부분 실현, 잔여 평가와 확인된 실제 비용·추정 비용의 구분을 유지한다. 필요한 값이 없으면 미확인으로 남긴다.
- 비용 후 손익 개선과 함께 낙폭·위험 초과·회전율·큰 승자 보존의 상충을 확인한다. 특정 승자에 의존한다는 이유만으로 조기익절을 권하지 않는다.
- 자료 누락·수정주가 기준 변경·사후 수집은 별도 품질 문제다. 이 때문에 검증할 수 없는 가설을 실패로 단정하거나, 유리한 불완전 결과를 성공으로 채택하지 않는다.

## 기존 보고서에 작은 판정표 추가

가설별로 `원래 기대 / 새 지지 증거 / 새 반박 증거 / 지난 검토 대비 변화 / 현재 판단 / 다음 결정·재검토 조건`을 짧게 정리한다. 근거 표본 수·관측 기간·자료 제한과 원본 보고서 참조를 함께 남긴다. 기존 구조화 출력이 있으면 같은 가설 ID로 연결한다.

판단은 지지·반박·혼재·자료 부족으로 설명한다. 다음 행동은 후보 유지·제외·범위를 정한 추가 검증·적용 검토 등 현재 권한 안의 제안으로 구분한다. 기한에 결론을 낼 근거가 부족하면 보류 사유와 재검토에 필요한 자료·사건을 명시한다. 기한을 자동 연장하거나 매일 새 규칙을 생성하지 않는다.

이 스킬 설치는 EOD 자동 연결이나 거래 권한을 부여하지 않는다. 운영 전략·보유분·위험 한도·서비스 상태는 연구 보고만으로 바꾸지 않는다. 별도 API·LLM 상시 호출 없이 기존 산출물만으로 처리할 수 있으면 그렇게 한다. 목표수익·주관적 확신 점수를 계산된 승률이나 검증된 기대수익처럼 표시하지 않는다.

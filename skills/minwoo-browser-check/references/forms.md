# 폼 전체 흐름

입력 → 검증 → 전송 중 → 성공/실패 → 재시도에서 요청한 폼에 해당하는 상태를 확인한다. 필드 모양 수정에 전체 접수 검사를 강제하지 않는다.

- 테스트 데이터·수신처·환경을 정한다. 실제 메일·문자·결제 전송은 허용된 외부 작업 범위에서만 수행한다.
- 빈 값·형식 오류·키보드 제출·전송 중 중복 클릭·서버 실패·연결 실패·재시도를 구현에 맞춰 확인한다. 버튼 비활성화만으로 서버 중복 방지가 증명되지는 않는다.
- 성공 문구·응답만 보지 말고 테스트 DB·메일 테스트 수신함·격리 서버의 접수 기록으로 연결한다. 요청·저장 건수·입력 값을 비교하되 비밀값은 보고서에서 제외한다.
- 서버 거절·저장 실패 때 성공 화면을 띄우지 않는지, 재시도가 중복 저장되지 않는지 확인한다. 증거 접근이 없으면 UI 성공/응답 성공/실제 접수 확인을 구분한다.
- check_browser.mjs는 DOM 동작을 검사한다. 저장·수신 증거는 프로젝트 테스트 API/DB/도구로 따로 확인한다. 운영 API가 읽기 전용이라고 추측해서 호출하지 않는다.

버튼·오류·완료 문구의 개선은 기존 UI 도구를 필요한 경우만 연결한다. 실제 시험한 상태·증거·미확인 단계를 보고한다.

# 공개 전 점검

공개하려는 파일과 이력이 적절한지 점검하고, 발견한 문제를 공개 내용에 노출하지 않고 알린다.

- 실제 공개 대상(새 저장소의 전체 파일, 기존 저장소의 변경, 포함될 Git 이력)을 먼저 구분한다. 확인 범위가 불명확하면 접근 가능한 범위를 점검하고 한계를 명시한다.
- 파일 목록과 `.gitignore`를 확인한다. 무시 규칙이 이미 추적 중인 파일이나 과거 커밋을 숨기지는 않는다. 인증 파일, 환경 파일, 개인 경로, 회사 전용 자료, 설치 상태·백업이 포함되는지 확인한다.
- 필요한 파일에서 비밀정보의 존재만 조사한다. 발견한 값, 비밀값이 포함된 줄, 개인 자료 본문을 출력하거나 외부 검사 서비스에 전송하지 않는다. 위치와 종류만 보고한다.
- 외부 코드·문서·이미지의 출처와 사용 조건을 확인한다. 공개되어 있다는 이유로 복사 권한이 있다고 판단하지 않는다. 모르면 불확실한 범위를 남긴다.
- README의 실행 예시, 실제 파일, 검증 결과가 일치하는지 확인한다. 예시 주소와 미완성 안내는 구분한다.

보고는 `확인 범위 / 발견 사항 / 공개 전에 필요한 조치 / 확인하지 못한 부분`으로 짧게 한다.
자동 검사만으로 비밀정보가 없다고 보장하지 않는다. 수정, 이력 변경, 저장소 생성, 커밋·푸시는 이 점검만으로 승인된 것으로 취급하지 않고 기존 사용자 요청의 범위를 따른다.

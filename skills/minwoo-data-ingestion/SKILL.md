# 파일과 대량 데이터 가져오기

입력 형식·크기·중복 키·처리 한도·적재 대상·실패 정책을 먼저 고정한다. 전체 성공/전체 취소와 부분 성공 중 실제 요구를 따른다. 데이터의 양과 신뢰 경계에 맞게 기존 스트림·파서·저장소를 사용한다.

- 확장자·클라이언트 MIME·원래 파일명을 신뢰하지 않는다. 업로드에는 서버 크기 한도, 인증/권한, 안전한 이름·저장 위치를 적용한다. 압축 파일은 해제 후 크기·경로 이탈도 제한한다. 필요한 상세 보안 검토만 기존 보안 스킬에 연결한다.
- 대형 파일을 전부 메모리에 올리지 말고 청크/행 단위 처리와 처리 속도 제어를 고려한다. CSV를 줄 단위 split으로 파싱하지 않는다. 인코딩·BOM·헤더·따옴표·셀 안 줄바꿈·잘못된 레코드를 명시적으로 다룬다.
- 행 식별, 중복 처리, 순서, 재실행 정책을 정한다. 같은 내용의 재시도와 같은 키의 다른 내용 충돌을 구분한다. 데이터 반영과 checkpoint 기록 사이 실패를 고려한다.
- 진행률의 분모(바이트/파싱 행/반영 행)를 정하고 성공·거절·처리 중을 구분한다. 중단 후 재개가 단순히 같은 파일인지 경로만 비교해서 판단되지 않게 파일 식별·스키마 버전 등을 확인한다.
- 부분 오류에는 필요한 행 번호와 원인만 남긴다. 개인정보 셀 전체를 로그에 남기지 않는다. 원본 파일 보존·임시 파일 정리·취소의 의미와 한도를 명시한다. 스프레드시트로 다시 내보낼 때 수식 주입 위험도 확인한다.
- 정상·경계 크기·잘못된 행·중복·중간 실패·재개·취소를 합성 자료로 시험한다. 메모리 사용과 처리량 개선을 주장하면 같은 크기·조건으로 측정한다.

작업 큐의 재시도는 minwoo-async-jobs, 화면 단계는 minwoo-state-flow, DB 스키마·트랜잭션 검토는 minwoo-postgres-review의 별도 역할이다. 운영 데이터를 시험용으로 복사하거나 실서비스에 적재하지 않는다.

# 실제 소비자 계약 시험

소비자가 실제로 쓰는 요청과 기대 동작에서 계약을 정한다. 제공자 구현의 응답을 그대로 복제해 기대값으로 쓰지 않는다. 요청 구성·응답 해석을 담당하는 실제 소비자 코드를 실행하고, 제공자도 알려진 fixture 상태에서 독립적으로 검증한다.

- 기존 Pact 같은 계약 도구가 있으면 재사용한다. 작은 앱은 기존 테스트 실행기로 로컬 제공자와 실제 소비자를 연결할 수 있다. 이 경우 Pact나 Broker를 사용했다고 보고하지 않는다.
- 필수 필드·타입·상태 코드와 실제 의미에 집중한다. 소비자가 무시하는 추가 필드나 객체 순서까지 고정해 불필요하게 깨지게 하지 않는다. 배열 순서가 계약인지 별도로 정한다.
- 정상 응답만 아니라 알려진 오류, 빈 결과, null/누락 구분, 인증 요구 변화 중 해당 소비자에 영향을 주는 경로를 확인한다. 미지원 명세 문법을 비교기가 통과했다고 호환으로 판단하지 않는다.
- 합성 데이터와 로컬/격리 제공자 상태를 사용한다. 실제 운영 호출·계약 외부 업로드·Broker 게시·배포 게이트 변경은 현재 허용된 범위에서만 한다.
- 알려진 비호환 변경에서 소비자 시험이 실패하고 호환 변경에서는 통과하는지 확인한다. 양쪽 버전·fixture 상태·실행 결과를 보고한다. 하나의 소비자가 통과했다고 모든 소비자·업무 기능이 검증됐다고 말하지 않는다.

# API 계약 호환성

기준 버전과 변경 버전, 기존 소비자, 실제 사용 중인 API 명세 형식을 먼저 고정한다. 저장소에 검증기·계약 테스트가 있으면 재사용한다. 요청은 기존에 허용하던 입력을 계속 허용하는지, 응답은 기존 소비자의 기대를 지키는지 방향을 구분한다.

OpenAPI 3.0/3.1 JSON의 간단한 변경에는 [제한형 비교기](references/usage.md)를 사용할 수 있다. 지원 밖의 문법·참조·의미 변화는 검토 필요로 남긴다. 도구의 0건 결과를 전체 API 호환성 보장으로 쓰지 않는다.

제거한 작업·매개변수, 새 필수 입력, 축소한 입력 값, 없어진 응답 필드·상태 코드, 인증 요구·페이지네이션·오류 의미 변화와 실제 호출자를 확인한다. 호환성을 유지하는 대안과 영향을 받는 소비자 회귀 테스트를 남긴다. 운영 API를 호출하거나 인증 정보를 복사할 필요는 없다.

보고에는 비교한 파일/커밋, 확인된 파괴적 변경과 검토 필요 항목, 테스트 결과·미검사 범위를 구분한다. 예시 payload와 원문 명세는 회사 정보가 있을 수 있으므로 공개 결과에 자동 포함하지 않는다.

실제 소비자와 제공자의 동작을 함께 검증할 때는 [실행 계약 시험](references/consumer-contracts.md)을 읽는다. 명세 diff와 실제 소비자 테스트의 증거를 구분한다.

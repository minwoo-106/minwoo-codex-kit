# 간헐적 테스트 실패

동일 커밋·환경에서 최초 실패와 재시도 성공을 따로 기록한다. 재시도 후 녹색 결과를 결함 해결로 보지 않는다. 반복 횟수·시간은 범위를 정하고 실제 실패 건수/시도 수를 남긴다.

- 단독/전체 실행, 순서, 병렬 worker, 시드, 시간대·시계, 전역/DB 상태, 비동기 완료 조건을 하나씩 대조한다. 무작위 반복만 늘이기보다 실패 조건을 고정한다.
- 재현되면 공유 가변 상태나 순서 의존을 격리하고, 임의 sleep 대신 실제 완료 조건을 기다리며 시계·네트워크를 테스트 경계에서 제어한다. timeout을 늘이는 수정은 실제 서비스 시간 근거가 있을 때만 사용한다.
- 테스트를 skip하거나 assertion을 약화하거나 재시도 횟수만 올리지 않는다. 격리가 필요하면 원인·영향·담당·복구 조건을 남기고 사용자의 범위에 따라 처리한다.
- 수정 전 실패 조건과 수정 후 같은 조건을 시험하고 반대 순서/관련 병렬 사례도 확인한다. 고정 횟수 통과를 절대 불규칙성 제거의 증명으로 표현하지 않는다.

브라우저 trace·CI 로그는 필요한 범위만 읽고 인증·개인 데이터를 공개하지 않는다. 관찰한 원인과 아직 재현 못한 가설을 구분한다.

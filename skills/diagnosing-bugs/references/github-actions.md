# GitHub Actions 실패 조사

현재 사용자의 수정·커밋·푸시 범위 안에서 진행한다. 이 안내가 재실행·배포·승인 권한을 추가하지 않는다.

1. 저장소, 브랜치/PR, head SHA, run ID, attempt, 실패한 job/step을 고정한다. 최신 커밋의 결과인지 확인하고 이전 실행의 녹색 결과를 현재 수정의 통과로 쓰지 않는다.
2. GitHub 연결 도구의 job 로그·체크 annotation을 우선 사용한다. 전체 로그 대신 첫 원인 오류와 필요한 주변 줄만 읽고 인증 정보·사용자 경로는 공개 기록에서 제외한다.
3. 코드/테스트 결함, OS·셸·경로 차이, 권한·secret 누락, 외부 서비스/runner 문제를 구분한다. 권한/서비스 문제를 코드 오류라고 가정해 무관한 파일을 수정하지 않는다.
4. workflow의 실제 명령·버전·작업 폴더·환경을 확인해 허용된 임시 환경에서 실패를 재현한다. OS별 코드 경로는 해당 runner에서 재확인한다. 테스트를 삭제·완화하거나 보안 제한을 풀어 통과시키지 않는다.
5. 원인이 확인된 최소 수정을 하고 관련 테스트를 실행한다. 푸시까지 요청된 작업이라면 해당 브랜치에 반영하고 새 SHA의 검사 결과를 확인한다. 같은 실패를 수정 없이 계속 재실행하지 않는다. 일시 장애 근거가 있을 때만 허용 범위에서 한 번 재시도하고, 반복되면 원인과 남은 조치를 보고한다.

보고에는 원인, 변경, 재현/검증 결과, 확인한 SHA·run 링크를 남긴다. 실제 GitHub 실행을 볼 수 없는 로컬 연습에서는 제공된 로그와 로컬 통과까지만 보고하며 원격 CI 성공을 주장하지 않는다.

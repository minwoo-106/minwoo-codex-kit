# 다국어와 지역화 구현

지원 언어·기본 언어·fallback·사용자 선택 저장 방식과 현재 번역 구조부터 확인한다. 번역 요청만으로 앱 구조를 바꾸지 않는다. 기존 i18n 라이브러리와 런타임 Intl 기능을 우선한다.

- 문장을 단어 조각으로 이어 붙이지 않는다. 번역 단위에 변수·문맥·복수형을 포함하고 빠진 키·변수의 처리 방식을 정한다. 영어의 단수/복수 규칙을 모든 언어에 적용하지 않는다.
- 숫자·화폐·날짜는 locale과 timeZone을 명시해 포맷한다. 언어와 국가·통화·시간대를 동일하게 가정하지 않는다. 시간대가 있는 순간, 날짜만 있는 값, 로컬 벽시계 시간을 구분해 저장 의미를 유지한다.
- 보간 값과 번역 리소스를 HTML처럼 무조건 실행하지 않는다. 앱 렌더러의 escaping 경계를 유지하고 변수 이름·링크 목적지·기술 식별자를 번역하지 않는다.
- 서버와 클라이언트의 초기 언어·시간대가 달라 화면이 바뀌는지 확인한다. 언어 전환 후 문구·형식·접근성 이름이 함께 갱신되는지, 긴 번역과 RTL에서 레이아웃이 유지되는지 해당 범위에서 시험한다.
- 복수형 0/1/2 등 언어에 필요한 범주, 빠진 키, 변수 누락, 시간대 날짜 경계와 DST 같은 관련 사례를 고정 입력으로 검증한다. 호스트 기본 locale과 현재 시각에 의존하는 테스트는 피한다.

번역문이 임시라면 제품용 검수 완료로 표현하지 않는다. 일반 번역·문체는 해당 글쓰기 흐름에 맡기고 UI 구현·검증에 집중한다. 브라우저를 실행하지 않았다면 포맷 함수 테스트와 화면 검증을 구분한다.

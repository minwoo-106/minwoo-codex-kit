# 상태 흐름 구현

현재 상태·이벤트·전이 조건·부작용·완료 상태를 구분한다. 여러 boolean이 표현하는 불가능한 조합을 찾고 필요한 경우 명시적인 상태로 정리한다. 간단한 토글을 큰 상태 머신으로 만들지 않는다.

- 유효한 전이와 무효 이벤트의 처리(무시/오류)를 공개 동작으로 정한다. 이전 단계로 돌아갈 때 유지·초기화할 데이터와 서버에 저장된 상태의 권한 주체를 명확히 한다.
- 순수 상태 전이와 네트워크·파일 같은 부작용을 분리한다. 요청 식별자나 세대 번호로 늦게 도착한 이전 응답이 새 상태를 덮어쓰지 못하게 한다.
- 중복 클릭·재진입·실패 후 재시도·취소 후 응답·새로고침/복원에서 필요한 동작을 확인한다. UI의 버튼 비활성화를 서버 중복 처리 방지의 증거로 쓰지 않는다.
- 상태 복원 시 저장된 버전·유효성을 검사한다. 과거 상태의 복원이 부작용 재실행을 자동 의미하지 않게 한다. 생명주기 종료 때 타이머·구독·요청을 정리한다.
- 전이 표의 주요 경로와 금지 경로, 늦은 응답을 실제 테스트한다. 화면 통합을 수정하면 제공되는 브라우저 도구로 관련 동작도 확인한다. reducer 테스트만으로 화면 검증을 했다고 말하지 않는다.

기존 reducer·상태 라이브러리를 먼저 쓴다. XState 도입을 기본값으로 삼지 않으며 필요 시 설치 버전의 API를 확인한다. 도메인 용어 합의는 domain-modeling, React 공개 API 구조는 minwoo-react-composition, 불변식 생성 시험은 minwoo-property-testing과 역할을 나눈다.

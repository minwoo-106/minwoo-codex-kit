# 근거 있는 릴리스 노트

1. 시작·끝 커밋을 고정하고 포함할 제품·독자·버전을 확인한다. Git 로그만으로 기능 완료를 추측하지 말고 변경 파일·실제 테스트·필요한 이슈 근거를 확인한다.
2. 사용자에게 영향을 주는 새 기능, 개선, 수정, 호환성 변경, 필요한 이전 작업으로 묶는다. 코드 정리·내부 테스트만 바뀌었다면 사용자 기능으로 부풀리지 않는다.
3. 미배포·실험 기능과 실제 배포된 기능을 구분한다. 릴리스 날짜·버전·공개 여부를 지어내지 않는다. 변경 없음도 허용한다.
4. 호환성이 깨지는 변경은 이전/이후 예와 사용자가 해야 할 일을 쓴다. 확인하지 못한 영향은 확인 필요로 남긴다.
5. 내부 경로·고객명·인증 정보·공개 전 보안 세부 사항을 제외하고, 허용된 공개 커밋·PR 링크로 근거를 연결한다.
6. 기존 CHANGELOG 형식을 유지한다. 문서 작성이 태그 생성·GitHub Release 게시·배포를 뜻하지 않는다. 그 작업은 사용자가 요청한 경우에만 수행한다.

별도 실행 도구는 Git뿐이다. 신규로 작성한 절차이며 출처가 불명확한 외부 changelog 스킬 본문은 복사하지 않았다.

# 앱 코드 보안 검토

검토 요청의 저장소·변경 범위·실행 환경을 고정한다. 언어와 프레임워크 버전, 진입점, 인증·권한 경계, 중요한 데이터를 실제 코드에서 확인한다. 해당 범위에 맞는 [검토 기준](references/checks.md)만 선택한다.

외부 입력이 위험한 처리에 도달하는 경로와 그 사이의 방어를 추적한다. 문자열 검색은 위치를 찾는 수단이며 취약점 판정은 아니다. 파일·줄·호출 관계·필요 조건·영향을 근거로 확정 사항과 추가 확인이 필요한 가설을 나눈다. 보이지 않는 미들웨어나 배포 구성을 없다고 가정하지 않는다.

보고서에는 중요한 발견부터 식별자, 위치, 재현 조건, 영향, 수정 방향, 확인하지 못한 범위를 남긴다. 실제 비밀값·사용자 데이터·운영 공격 요청은 결과물에 넣지 않는다. 테스트가 필요하면 로컬 합성 데이터와 격리 환경을 쓰고, 프로젝트의 기존 테스트를 재사용한다.

검토만 요청됐으면 파일 수정 없이 보고한다. 수정까지 이미 허용됐다면 다시 포괄 승인을 요구하지 말고 해당 범위에서 수정·회귀 검증을 수행한다. 승인 설정을 바꾸지 않으며 운영 데이터·계정·서비스 변경 권한을 이 스킬에서 새로 만들지 않는다.

패키지의 알려진 취약점은 minwoo-dependency-audit의 역할이고, 일반 변경 품질은 code-review의 역할이다. 이 스킬의 결과를 전면 침투 시험이나 모든 취약점 부재의 증명으로 표현하지 않는다. 지원 언어 밖에서는 범위를 밝히고 해당 기술의 공식 보안 문서를 먼저 확인한다.

# 보안 발견의 증거와 반증

보안 문제 후보를 보고하거나 수정 효과를 검증할 때 읽는다. 전체 침투 시험·별도 에이전트·보고서 파일 생성을 자동으로 시작하지 않는다.

- 요청 범위의 커밋/변경과 실행 환경을 고정한다. 낮은 신뢰 주체, 제어 가능한 입력, 서버의 의도된 통제, 실제 호출 경로, 영향을 받는 다른 주체/자원과 결과를 연결한다. 위험한 함수 이름이나 빠진 권장 설정만으로 취약점을 확정하지 않는다.
- **확인됨**은 소스·설정 또는 허용된 재현으로 경계 위반의 조건과 결과가 입증된 경우다. 실제 실행하지 않았다면 소스 분석으로 확인한 범위를 명시한다.
- **추가 검증 필요**에는 빠진 배포 설정·미들웨어·권한 조건을 적고 무엇으로 확인할지 제시한다. 확정 취약점과 같은 심각도나 발생 건수에 합산하지 않는다. 외부 배포가 보이지 않는다는 이유로 방어가 없다고 가정하지 않는다.
- **기각**은 실제 방어·도달 불가능한 경로·같은 사용자에게만 생기는 효과 등 반증이 확인된 경우다. 단순 재현 실패는 기각의 충분한 근거가 아니다. 조사하지 않은 경로는 안전한 경로로 표시하지 않는다.
- 중요도는 입증된 피해·접근 조건·영향 범위에 맞춘다. 여러 후보가 같은 근본 원인이면 묶고, 가능성이나 우려를 실제 피해 규모처럼 부풀리지 않는다.

## 안전한 재현과 대조군

요청과 실행 권한 안에서 합성 사용자·로컬 사본·기존 테스트로 최소 효과만 확인한다. 출처를 검토하지 않은 대상 코드·빌드·의존 설치는 호스트 자격 증명과 네트워크에 접근할 수 있으므로 단순 임시 폴더를 보안 샌드박스로 부르지 않는다. 필요한 격리를 제공할 수 없으면 실행을 생략하고 부족한 조건을 보고한다.

한 객체에 대해 허용된 사용자와 다른 사용자를 함께 시험한다. 안전한 바인딩·이스케이프·서버 소유권 검사도 대조군으로 둔다. 수정 뒤에는 정상 경로의 통과와 공격 조건의 차단을 둘 다 확인하며, 테스트가 해당 함수를 실제 호출했는지 확인한다. 운영 URL·다른 사용자의 데이터·실제 비밀값은 재현에 쓰지 않는다.

기록에는 위치, 조건, 경계/영향, 확인 방식(소스/로컬 실행/실제 환경), 반증 시도, 가장 작은 수정안, 남은 검증을 담는다. 읽기 전용 검토는 보고로 끝내고, 수정까지 허용됐다면 중복 승인 없이 관련 회귀 검증까지 진행한다.

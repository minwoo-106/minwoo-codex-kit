# 필요한 경계만 조사

- 인증과 객체 권한: 로그인 여부와 요청한 데이터의 소유권·테넌트 권한을 구분한다. 서버에서 각 접근을 검증하는 경로와 누락되는 예외 경로를 확인한다. UUID는 권한 검사를 대신하지 않는다.
- SQL: 외부 입력이 문자열 조립을 거쳐 실행되는지, 파라미터 바인딩과 허용 목록이 실제로 사용되는지 추적한다. ORM 사용 사실만으로 안전하다고 판정하지 않는다.
- HTML·스크립트: React의 일반 문자열 출력과 raw HTML 삽입을 구분한다. 출력 위치에 맞는 인코딩·검증된 정화와 서버·클라이언트 양쪽 흐름을 확인한다. CSP 하나로 입력 처리를 대체하지 않는다.
- 파일·명령·역직렬화: 입력 경로의 허용 범위, 심볼릭 링크, 명령 인수 경계, eval 또는 신뢰하지 않는 직렬화 자료의 실행 가능성을 확인한다.
- 네트워크 요청: 사용자 입력 URL이 내부 주소·리디렉션·인증 헤더 전달에 미치는 영향을 조사한다. 개발 환경의 로컬 URL만 보고 운영 SSRF로 단정하지 않는다.
- 세션·CSRF·쿠키·CORS: 인증 수단과 브라우저 요청 경로를 기준으로 본다. TLS 종료 위치·개발용 HTTP를 구분하고 쿠키·보안 헤더를 맥락 없이 일괄 변경하지 않는다.
- 민감 데이터: 로그·오류 응답·클라이언트 번들·테스트 자료에 실제 값이 나가는지 확인한다. 발견한 값을 보고서에 재출력하지 않는다.
- 버전별 기본값: Python 프레임워크, Node/React/Next.js, Go 표준 라이브러리의 현재 코드·공식 문서를 확인한다. 현재 범위에 없는 프레임워크의 규칙을 모두 읽지 않는다.

확인용 대조군도 살핀다. 파라미터 SQL, 프레임워크가 이스케이프하는 텍스트, 서버에서 소유권을 검사한 요청을 같은 위험 함수 이름이 있다는 이유로 취약하다고 보고하지 않는다.

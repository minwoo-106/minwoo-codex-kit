# kit 점검·갱신

원본 저장소는 https://github.com/minwoo-106/minwoo-codex-kit 이다.
사용자가 지정한 로컬 사본이 있으면 그 위치를 사용하고 원격 주소·적용 지침·Git 상태를 확인한다.
이 스킬이 설치된 폴더를 kit 저장소로 가정하지 않는다.

## 차이 확인

제공된 Python 3.10+ 도구는 네트워크 접속이나 쓰기 없이 kit 관리 대상의 파일 상태를 JSON으로 출력한다.

```text
python <이 스킬 폴더>/scripts/inspect_kit.py --kit <로컬 kit 경로>
```

경로를 바꾼 환경은 --codex-home과 반복 가능한 --skills-root를 지정한다.
기본 스킬 위치는 ~/.agents/skills와 실제 Codex 홈의 skills다.
출력에는 로컬 경로가 들어가므로 공개 저장소에 그대로 저장하지 않는다.

- absent는 해당 경로에 설치되지 않았다는 뜻이다. 오류나 설치 필요 판정이 아니다.
- different는 파일 바이트 차이다. 원본이 더 최신이거나 사용자 수정이 틀렸다는 뜻이 아니다.
- extra는 원본에 없는 설치 파일이다. 자동 삭제 대상으로 취급하지 않는다.
- duplicates는 같은 이름의 스킬이 여러 위치에 있다는 뜻이다. 플러그인 캐시까지 모두 조사한 결과가 아니다.
- 링크·정션이 발견되면 도구는 중단한다. 실제 경로를 확인하며 우회 설치하지 않는다.

## 갱신 요청인 경우

- 읽기 전용 점검이면 차이 보고로 끝낸다. 갱신까지 요청된 경우에는 이미 주어진 권한 범위에서 계속한다.
- 원격 상태가 필요하면 GitHub 도구 또는 fetch로 확인한다. 로컬 변경·분기 이력이 있으면 임의로 reset·stash·강제 pull하지 않는다.
- 원본을 갱신할 수 있는 깨끗한 작업 트리에서만 fast-forward를 적용한다. 새 스킬 전체를 자동 선택하지 않는다.
- 기존 README의 설치 옵션을 확인하고 선택한 대상·경로로 --dry-run을 먼저 수행한다. 규칙을 유지하는 스킬 갱신은 --skip-rules를 사용한다.
- 충돌 시 로컬 수정과 원본의 차이를 보존·병합한다. --replace-existing은 사용자가 해당 교체를 허용했고 차이를 검토한 경우에만 쓴다. 범위가 명확하면 매 단계 재승인을 요구하지 않는다.
- 설치 후 선택한 파일·백업·반복 실행의 무변경을 확인한다. 원본에서 사라진 파일은 자동 제거되지 않으므로 별도 보고한다.
- 외부 스킬은 카탈로그의 개별 갱신 절차, 플러그인은 해당 관리 기능을 따른다. 승인·인증 설정과 플러그인 캐시는 변경하지 않는다.

결과에는 실제 갱신한 대상, 유지한 로컬 수정, 검증·원격 확인 범위를 남긴다.

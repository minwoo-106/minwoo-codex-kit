# 의존성 업그레이드

요청한 패키지와 목표 버전·범위를 확인하고 현재 manifest, lockfile, 런타임, 실제 import/호출을 읽는다. 최신 버전을 임의로 가정하지 않는다. 사용 중인 패키지 관리자를 유지한다.

1. 현재 테스트 결과를 남기고 공식 변경 기록·이전 안내에서 제거된 API, 기본값 변화, peer/runtime 요구를 확인한다. 업데이트가 필요한 직접 의존성과 따라 바뀌는 전이 의존성을 구분한다.
2. 연관된 패키지 묶음만 작은 단위로 갱신한다. unrelated 최신화, 잠금 파일 삭제, force 설치, 감사 오류 무시를 기본 해결책으로 쓰지 않는다. 기존 lock 생성 옵션·registry를 유지하며 인증 값은 출력하지 않는다.
3. 버전 번호만 바꾸지 말고 실제 호출·타입·설정의 변경을 반영한다. codemod는 먼저 범위와 결과를 검토한다. 충돌 때문에 기존 코드를 통째로 재생성하지 않는다.
4. 잠금 기반 재설치를 격리된 작업 환경에서 확인하고 타입/빌드/관련 실행 테스트를 수행한다. npm ci 같은 명령이 node_modules를 교체한다는 점을 고려한다. 패키지 설치 스크립트의 권한과 네트워크 범위를 무조건 확대하지 않는다.
5. manifest와 lock의 일치, 불필요한 전이 변경, 기존 동작과 새 API 사용을 검토한다. 실패하면 원인을 분리하며 이전 커밋·잠금 상태로 복구할 경로를 설명한다. 사용자의 기존 변경을 reset하거나 lock을 임의 되돌리지 않는다.

결과에는 실제 이전/새 버전, 호출 변경 이유, 검증과 남은 호환성 문제를 적는다. 보안 조사만 필요하면 minwoo-dependency-audit를 사용하며 모든 업그레이드에 별도 전체 보안 감사를 강제하지 않는다. 실행 환경이 없으면 계획과 실제 반영을 구분한다.

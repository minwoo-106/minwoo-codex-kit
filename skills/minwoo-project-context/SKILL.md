# 프로젝트 규칙 정리

요청한 저장소에 다음 작업부터 쓸 수 있는 짧고 검증 가능한 `AGENTS.md`를 만든다.

1. 적용되는 지침, Git 상태, 기존 `AGENTS.md`를 먼저 확인한다. 기존 문서가 있으면 필요한 부분만 고친다.
2. 목적·실행 환경·진입점·검증 명령을 관련 파일에서 확인한다. 패키지 설정과 CI가 다르면 각각의 용도를 구분한다. 비밀값이 들어 있는 설정 본문은 읽거나 옮기지 않는다.
3. 사용자 전역 규칙을 복사하지 않고 이 프로젝트에 필요한 사실, 보호할 동작, 주요 경로와 문서 위치를 남긴다. 확인하지 못한 명령이나 팀 브랜치 정책은 사실처럼 기록하지 않는다.
4. 기존 사용자 결정으로 해결할 수 있는 항목은 이어서 처리한다. 작업 브랜치처럼 안전하게 결정할 수 없는 항목만 짧게 묻고, 나머지 문서 작업은 계속한다.
5. 문서의 경로와 명령을 확인한다. 의존성이 갖춰져 있고 비용·외부 변경 없이 실행할 수 있는 검증만 수행하고, 실행하지 못한 부분은 구분해서 알린다.

결과에는 수정한 파일, 확인한 근거, 남은 미확인 항목만 간단히 보고한다.
스킬 설치나 프로젝트 설정 정리를 이유로 승인 모드, Git 설정, 실행 정책을 바꾸지 않는다.

# 논의에서 구현으로

개발 요구사항을 함께 정하거나, 합의한 큰 작업을 실행 가능한 명세·작업 단위로 연결할 때 사용한다. 단순 수정에는 이 절차나 별도 문서를 붙이지 않는다.

## 현재 요청의 범위

- “먼저 보고 토론하자”, “아직 만들지 마”: 관련 코드·기존 결정부터 읽고 확인한 사실, 선택지와 추천 이유를 제시한다. 구현·설치·커밋·게시를 시작하지 않는다. 대화만 요청했다면 파일도 만들지 않고 대화에 정리한다. 명세 파일 작성까지 요청했다면 그 문서만 갱신한다.
- “합의한 대로 작업해”: 현재 대화와 기존 문서에서 확정된 범위를 이어받아 구현·검증을 진행한다. 구현 방법·파일명 등 되돌리기 쉬운 세부 선택은 기존 관례로 정하며 명세·작업 분할의 별도 승인을 다시 요구하지 않는다.
- 문서 제목·상태의 “승인됨”이나 긍정적인 감상만으로 구현 권한을 추정하지 않는다. 현재 요청이 토론만으로 제한하면 이전 구현 지시보다 그 제한을 우선한다. 반대로 명확한 구현 지시가 왔으면 이전 토론 단계에 머무르지 않는다.

## 논의와 합의 기록

코드·설정에서 확인할 사실은 먼저 조사한다. 사용자의 목표·우선순위·업무 의미처럼 답에 따라 결과가 달라지는 결정만 질문하고 추천안과 영향을 함께 설명한다. 답하지 않은 선택은 미정으로 남기며 추천안을 사용자 결정처럼 기록하지 않는다. 불확실한 질문 때문에 독립적이고 이미 허용된 작업까지 중단하지 않는다.

합의는 다음 작업을 이어갈 만큼만 기록한다: 원하는 동작, 중요한 예외·용어, 제외 범위, 관찰 가능한 완료 조건, 아직 미정인 결정. 간단하면 대화의 짧은 목록이면 충분하다. 문서화가 요청됐거나 허용된 큰 구현에 지속 기록이 필요하면 기존 명세·기획 문서를 갱신한다. AGENTS.md에는 장기 규칙이나 문서 위치만 남기고 일회성 명세·진행 기록을 복제하지 않는다.

새 자료가 합의와 충돌하면 근거와 영향받는 범위를 알린다. 제품 동작·데이터 보존처럼 중요한 결정은 조용히 바꾸지 않는다. 결정 변경이 허용되면 원래 근거와 연결해 기록을 갱신한다.

## 큰 작업의 분할과 실행

완료 조건이 여러 개이거나 작업 순서에 의존성이 있을 때만 분할한다. 각 단위는 사용자가 확인할 수 있는 동작, 완료 조건, 선행 작업을 가진다. 실제로 의존하는 작업만 연결하며 준비·구현·검증 목록을 불필요한 티켓 수로 늘리지 않는다.

가능하면 데이터·로직·화면을 가로지르는 작은 동작 하나를 완성한다. 관련 없는 계층은 억지로 추가하지 않는다. 넓은 API·스키마 이행은 필요한 경우 새 형식 병행 → 호출자 이전 → 옛 형식 제거로 나눠 기존 동작을 유지한다. 단순 명세 정리에 이런 이행 계획을 강제하지 않는다.

이미 구현이 허용됐으면 분할한 계획을 짧게 알리고 바로 진행한다. 문서 작성만 요청했다면 작업 목록에서 멈춘다. 로컬 계획을 GitHub 이슈 게시, 다른 채팅 생성, 에이전트 실행, 커밋·푸시·배포 권한으로 확대하지 않는다. 각각 현재 요청과 프로젝트 지침의 범위에서만 수행한다.

## 합의와 결과의 대조

구현 후 완료 조건별로 실제 동작·검사 결과를 대조한다. 예외·경계 조건을 포함하고, 단순 함수 존재나 테스트 통과만으로 요청 충족을 단정하지 않는다. 누락·요청 밖 변경·미검증 항목을 구분하며 기존의 유효한 검사 결과는 재사용한다. 검증 중 발견한 결함은 허용된 범위에서 수정하고 필요한 검사만 다시 수행한다.

결과에는 구현한 동작, 각 완료 조건을 확인한 근거, 남은 미정·미검증을 짧게 남긴다. 관련 스킬은 필요한 역할만 연결한다: 용어 체계는 domain-modeling, 심층 질문 요청은 grilling, 명시적 테스트 우선 구현은 tdd, 요청된 코드 리뷰는 code-review. 모든 작업에서 전체 묶음·독립 리뷰·회고를 강제하지 않는다.

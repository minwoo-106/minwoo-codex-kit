# 공개 사례로 보고서 구성하기

먼저 독자가 보고서를 읽고 답해야 할 질문을 한 문장으로 정한다. 예를 들어 시범 운영 결과라면 ‘다음 달에도 같은 조건으로 운영할까?’다. 결과물이 파일이면 해당 형식의 제작·렌더 도구를 사용한다.

## 사례에서 가져올 것

- 독자와 용도가 비슷한 공개 보고서나 발행기관의 공개 양식 두 건 이상을 직접 연다. 검색어에는 문서 종류·용도만 쓰고 내부 메모, 회사명, 수치와 미공개 계획은 넣지 않는다.
- 실제 지면을 보고 각 사례에서 선택할 편집 판단을 구체화한다. 예를 들어 첫 사례에서 요약문의 결정 사항 배치를, 둘째 사례에서 비교표에 기준 기간과 단위를 붙이는 방식을 참고할 수 있다. 같은 문서의 복제본은 한 건으로 센다.
- 문체·로고·도안을 복제하거나 사례 속 수치로 빈칸을 채우지 않는다. 사용자가 제공한 양식이 있으면 그 양식을 우선한다. 웹 검색이 제한되면 제공된 참고 자료로 진행하고 확인한 범위를 보고한다. 사례가 부족해도 작성 가능한 초안은 제공한다.

## 초안에서 완성본까지

1. 원문에서 확정된 사실, 비교 조건, 남은 결정을 구별한다. 결정이 미정이면 첫 문단에서 그렇게 말한다. 요청하지 않은 결론·담당자·기한을 만들어 넣지 않는다.
2. 메모가 뒷받침하는 항목만 배치한다. 독자가 승인·보류 이유를 찾을 수 있게 핵심 조건을 해당 수치나 조치 가까이에 둔다. 양식에 필요하지 않은 머리말이나 작성자의 맺음말은 덧붙이지 않는다.
3. 숫자·날짜·단위·부정·미확정 상태를 원문과 대조한다. 별도로 사례를 다시 보며 정보 순서가 독자의 판단에 맞는지 확인한다. 파일이면 실제 크기로 렌더해 줄바꿈과 잘림까지 보고, 발견한 문제를 고친 뒤 해당 페이지를 다시 본다.
4. 납품 답변에는 실제 열어본 사례 링크와 반영한 점을 짧게 적는다. 미검토 자료를 참고했다고 쓰거나 수정 이력을 꾸미지 않는다. 사례 출처와 보고서 자체의 사실 출처는 구분한다.

# 백그라운드 작업과 재시도

작업의 입력, 부작용, 성공 판정, 중복 전달 가능성, 복구할 상태를 먼저 정한다. 기존 큐·저장소·worker 구조를 재사용한다. 짧은 함수 하나에 새 큐 서비스를 도입하지 않는다.

- 영구 실패와 일시 실패를 나누고 횟수·전체 시간·지연에 상한을 둔다. backoff와 jitter는 재시도 폭주를 줄이는 수단이며 모든 오류를 재시도하는 근거가 아니다. 테스트에서는 시계·sleep·난수를 주입할 수 있게 한다.
- 재시도 시 같은 업무를 식별할 키와 보존 기간을 정한다. 키 등록과 결과 기록의 원자성, 동시에 같은 작업을 받은 경우를 고려한다. 메모리의 완료 목록만으로 여러 worker·재시작까지 중복 방지됐다고 말하지 않는다.
- 외부 부작용 직후 기록 전에 죽는 구간을 검토한다. 외부 시스템의 멱등 키, 트랜잭션/outbox 등 실제 경계에 맞는 방식이 없으면 정확히 한 번 처리를 보장하지 않는다.
- 취소는 요청됨과 실제 중단됨을 구분한다. 비가역 부작용 이후 취소의 의미를 정하고 중단 위치·재개 가능 여부·종료 시 진행 작업 처리를 명시한다. 실패 작업의 수동 재처리도 승인된 범위에 한정한다.
- 동시성·대기열·입력 크기에 한도를 둔다. worker보다 빠른 생산 속도에 대응하고 대형 payload·민감정보를 큐와 로그에 불필요하게 복제하지 않는다.
- 중복 전달, 일시 실패 후 성공, 영구 실패, 재시도 소진, 취소, 가능한 crash 경계를 시험한다. 단일 프로세스 테스트와 실제 큐/DB의 원자성 검증을 구분한다.

화면의 단계 이동은 minwoo-state-flow, 파일 파싱·부분 적재는 minwoo-data-ingestion이 맡는다. 작업 식별·실행·재시도 부분만 이 스킬에서 다룬다. BullMQ 등 특정 서비스는 프로젝트가 선택한 경우에만 연결한다.

# 속성 기반 테스트

기존 TDD·테스트 규칙을 유지하면서 예제 몇 개로 놓치기 쉬운 성질을 검증한다.

1. 공개 계약에서 불변식·왕복 관계·참조 모델을 찾는다. 구현과 같은 계산을 그대로 복제하는 검증은 피한다.
2. 프로젝트에 설치된 라이브러리·테스트 실행기를 우선한다. Python은 Hypothesis, JS/TS는 fast-check가 후보이며 필요한 언어 하나만 사용한다. 새 의존성 추가는 현재 사용자가 허용한 범위에서 한다.
3. [생성기 설계](references/generating.md)와 [라이브러리 선택](references/libraries.md) 중 필요한 문서만 읽는다. 유효 입력을 직접 생성하며 대부분을 버리는 필터·무의미한 참 조건을 피한다.
4. 일부러 틀린 작은 구현이 실패하는지 확인하고, 실제 코드에 적용해 실패 입력을 축소한다. [실패 해석](references/interpreting-failures.md)을 따라 요구사항·생성기·코드를 구분한다.
5. 재현 seed·최소 반례를 남기고 테스트가 우연히 통과하지 않는지 확인한다. 무한 실행 대신 프로젝트에 맞는 실행 횟수를 정한다.

기존 테스트 검토는 [리뷰](references/reviewing.md), 테스트 개선은 [리팩터링](references/refactoring.md)을 필요할 때 읽는다. 이 스킬은 별도 계획 승인이나 테스트 우선 개발을 모든 작업에 강제하지 않는다. 참고 문서의 제안보다 현재 작업의 승인 범위를 먼저 적용한다.

선택 도구 묶음의 fast-check·Hypothesis 검증은 kit의 `docs/TOOLS.md` 참고. [출처와 변경 사항](UPSTREAM.md).

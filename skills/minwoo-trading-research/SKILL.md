# 자동매매 연구와 자금 활용 진단

운영 전략 변경, 연구 후보 구현, 읽기 전용 진단 중 요청 범위를 먼저 구분한다. 연구 허가는 운영 전략·한도·보유분·서비스 시작/중지 허가로 확대하지 않는다. 기존 주문·포지션 계산과 연구 엔진을 가능한 한 재사용한다.

## 자료와 비교 기준

- 실제 체결 계좌, 가상 기준선, 후보 성과를 구분한다. 같은 가상자본·기간·관측 가능 자료·체결·비용으로 후보를 비교한다. 자료 범위나 보유기간이 다르면 별도 실험으로 표시한다.
- 운영 DB 분석에는 기존 정산 복사본을 우선한다. 새 복사본이 꼭 필요하면 잠금 대기·전체 실행 제한을 둔 백업 후 운영 연결을 닫는다. 긴 분석·전체 스캔을 운영 연결에서 수행하지 않는다. 기존 캐시를 우선하고 추가 수집·주문 권한을 추정하지 않는다.
- 완료봉 시각, 실제 저장 시각, 주문 가능 시각을 구분한다. 신호를 만든 종가에 즉시 체결하지 않는다. 뒤늦게 모은 가격으로 과거 경로를 복원한 결과는 당시 관측/Forward와 구분한다.
- 열린 가상 포지션은 후보 목록에서 빠져도 관리한다. 누락 시가·거래정지·기업행동을 보간하거나 마지막 가격으로 강제 청산하지 않는다. 원주가만 있으면 분할·배당·상장폐지와 과거 위험분류 미확인을 명시한다.
- 연구 후보의 정의·소스 해시·등록 시각을 먼저 고정한다. 기존 평가 자료로 규칙을 고른 결과를 새로운 미사용 검증으로 표시하지 않는다.

## 자금이 남는 이유

신호 부족, 슬롯, 진입 횟수, 거래당 위험, 전체 위험, 종목당 금액, 현금/예약, 상관 집중, 시간 제한, 데이터/운영 차단을 나눈다. 저장된 선행 차단 사유는 동시에 작동한 모든 제약을 설명하지 않는다. 기록되지 않은 당시 현금·보호가격·우선순위는 추정 확정하지 않는다.

`투자금 ≈ 허용 위험액 ÷ 진입가 대비 손절 거리`를 실제 정수 수량·예외·상한과 대조한다. 계좌 현금, 매입 원가, 평가금 노출, 예정 손절 위험, 실현된 최대낙폭은 서로 다른 값이다. 같은 규칙에 돈만 더 넣어 수익이 늘면 위험 확대 효과도 함께 표시한다.

## 후보와 평가

자금배분·종목선정·진입·청산 중 변경 축을 명시한다. 여러 요소를 바꾸는 후보는 조합 실험으로 표시한다. 여러 후보를 연구한다는 이유로 실제 주문 서비스를 여러 개 띄우지 않는다.

완료 포지션, 부분실현, 잔여 평가를 분리한다. 확인된 실제 비용과 추정 비용도 분리하고 체결가에 반영된 가격차를 다시 차감하지 않는다. 비용 후 기대손익·PF·승률·실현 낙폭·평가 포함 낙폭·회전율·노출·예정 위험 초과 손실을 함께 본다. 없는 가격으로 계산한 낙폭은 정확한 계좌 MDD로 보고하지 않는다.

큰 승자 보존은 종목명뿐 아니라 신호 시각·진입 유형으로 연결한다. 미진입, 다른 시각 진입, 잔여 보유, 조기청산을 구분한다. 최대 승자 제외 성과가 약하다는 이유만으로 익절을 앞당기지 않는다. 시장 부진이나 낮은 승률만으로 전략을 단정하지 않고 비용 후 기대값과 시장 상태별 증거를 함께 검토한다.

세부 검증과 보고가 필요하면 [실험 검증 기준](references/validation.md)을 읽는다. 공개 프레임워크를 참고하거나 복사하려면 [출처와 재사용 범위](references/sources.md)를 먼저 확인한다. 코드 변경·실험·배포를 실제 완료한 범위와 막힌 범위로 나눠 보고하며 자동 승격을 추가하지 않는다.

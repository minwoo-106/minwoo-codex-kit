# 웹 품질 실전 평가

기본 unittest에 SEO 8개를 포함한다. 실제 브라우저·모델 실행은 아래 명령으로 분리한다. 출력 폴더는 매번 새 경로여야 한다.

```sh
# setup-tools.py가 출력한 별도 런타임 사용. 기존 브라우저는 --browser <실행 파일>로 지정.
node evals/verify_quality.mjs --runtime <runtime> --out <new-output>
# 계획 확인: 모델 호출 없음
python -B evals/run_web_reviews.py
# 현재 사용자의 로그인·기본 모델로 실제 실행. 사용량 발생.
python -B evals/run_web_reviews.py --run --out <new-output>
```

브라우저 시험은 로컬 서버의 합성 페이지에서 접근성 정상·위반, 기준 생성, 같은 화면·변경 화면, 기준 덮어쓰기·변조 거절, 원격 주소 미허용 거절 8개를 확인한다. 별도 입력 방어 검사도 수행한다. 실패 화면에서는 실제 차이 이미지가 있어야 하며 비교로 기준 파일이 변하면 실패한다. 기준은 같은 OS·브라우저·화면 크기에서만 재사용한다.

모델 시험은 PC에 설치된 보안·SEO 스킬을 명시한다. 보안은 SQL 문자열 연결과 HTML 삽입 문제가 있는 파일 및 안전한 반례를 주고, 소스 변경 없이 위치·근거·수정 방향이 있는 JSON 보고서를 요구한다. SEO는 제공된 스냅샷을 실제 검사 스크립트로 검사하게 한다. 성공한 전체 스킬 읽기, 정상 종료, 입력 해시 보존, 외부 도구 미사용, 결과물 검증을 모두 요구한다. 보안 보고서는 결과 내용을 수동으로도 검토한다.

모델의 읽기 전용 선택 시험과 전체 작업 수행 시험은 별개다. 원시 로그·브라우저 trace·화면·개인 경로는 로컬에 보관하고 검수한 요약만 공개한다. 모델 서버 오류 등 최초 실패와 재시험 결과를 구분한다. 승인·모델의 저장 설정을 변경하지 않는다.

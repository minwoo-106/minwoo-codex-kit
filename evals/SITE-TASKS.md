# 홈페이지 스킬 실제 평가

```text
node evals/verify_site.mjs --runtime <runtime> --browser <선택한 브라우저 실행파일> --out <새 폴더>
python -B evals/run_site_tasks.py
python -B evals/run_site_tasks.py --run --runtime <runtime> --browser <브라우저 실행파일> --out <새 폴더>
```

브라우저 평가 13개는 정상 경로·링크/앵커/이미지 결함·공유 정보 미확인·반복 측정·명시 시간 기준 초과·입력 거절·출력 보존·폼 빈 값·중복 클릭·서버 실패·재시도를 확인한다. 폼은 실제 로컬 서버의 접수·저장 건수와 값을 대조한다. 이는 클라이언트 중복 클릭 방어 시험이며 운영 서버의 동시성·재전송 멱등성이나 실제 메일 전달 시험이 아니다.

모델 평가 4개는 브랜드/문구, 기획, 자산, 출시다. 스킬을 명시한 실제 작업 평가로 자동 선택 시험과 구분한다. 성공한 전체 스킬 읽기, 입력 보존, 외부 도구 미사용, 정상 종료와 JSON 결과를 확인한다. 자산 파일 크기는 실제 바이트와 대조하고 출처가 없는 가짜 폰트를 사용 가능으로 단정하지 않아야 한다. 출시 사례는 실제 로컬 사이트와 설치된 검사기를 사용해 404를 발견해야 한다.

창작 JSON의 자동 검사는 구조와 작업 완료 증거만 확인한다. 내용의 사실성·어조·다양성은 결과물을 직접 읽고 별도로 기록한다. 모델 평가를 실제 고객 조사·사용성 테스트·전환 실험으로 표현하지 않는다. 원시 로그·개인 경로·결과물은 로컬에만 두고 검수한 요약을 공개한다.

기본 명령은 계획만 출력한다. --run은 현재 사용자의 로그인·기본 모델 사용량이 발생한다. 저장된 승인·모델 설정을 수정하지 않는다. 실패 시 새 출력 폴더와 --case로 필요한 사례만 다시 실행하며 최초 실패를 보존한다.

# 코드 단순화 지침의 전후 비교

Ponytail 원문을 설치하는 시험이 아니라 기존 kit 지침과 선택 보강한 지침의 실제 코드 결과를 비교한다. 기본 실행은 계획만 출력한다.

```text
python -B evals/run_simplification.py
python -B evals/run_simplification.py --run --out <저장소 밖의 새 개인 폴더>
```

`--before-ref` 기본값은 보강 전 커밋 `6e4b899d4070a266ef20416ad09aae90b8ba48a3`이다. 이 커밋이 있는 Git 작업 사본이 필요하며, 보강 후는 실행 시 작업 트리의 파일을 사용한다. `--case reuse`, `--case duplicates`, `--case strict-date`로 과제를 선택할 수 있다. 현재 로그인·기본 모델을 쓰며 저장된 승인 설정을 변경하지 않는다. 실제 실행은 모델 사용량이 발생한다.

두 조건은 같은 합성 Python 코드·요청·기존 테스트를 받는다. 전역 규칙, 리팩터링 안내, 측정 안내만 다르고 각 세션은 새 작업 폴더에서 실행한다. 순서는 전/후, 후/전, 전/후로 교대한다. 지침을 명시적으로 읽도록 하므로 자연어 자동 선택 시험은 아니다. 상위 환경 규칙과 설치 목록은 두 조건에 공통으로 남는다. 설치본 갱신 전에 수행하며 외부 스킬 로딩·도구 사용 여부는 trace로 별도 확인한다.

| 과제 | 확인할 동작 |
| --- | --- |
| CSV 내보내기 확장 | 기존 도우미 재사용, CSV 이스케이프·LF·빈 입력, 정확한 True 판정, 일회용 iterable, 제외 행 검증 생략 |
| 주문 집계 정리 | SKU 첫 등장 순서·합계·0, 취소 행 포함 입력 검증, 예외 메시지, 입력 보존 |
| 예약 날짜 정리 | ASCII 날짜 형식·윤년·주말·금지일·검사 우선순위·반환 타입 |

기존 테스트 보존과 모델이 작성한 추가 테스트를 실행하고, 모델에게 공개하지 않은 고정 검사기로 각각 36·94·94개 입력을 검증한다. 반환값뿐 아니라 오류 메시지·부작용을 비교한다. 검사기는 별도의 회귀 시험으로 정상 구현 통과와 의미 있는 결함의 탐지를 확인한다.

```text
python -B -m unittest discover -s tests -p test_simplification_eval.py -v
```

성공한 명령 출력에서 지침 전체 읽기, 허용된 파일만 변경, 외부 도구 이벤트 부재, 세션 완료, 모델 테스트와 독립 검사 통과를 확인한다. 명령 안전성·불필요한 승인 질문·가독성·실제 테스트 실행 주장은 원시 trace와 산출물을 수동 검토해야 한다. 자동 판정이 모든 안전성을 증명하지 않는다.

생산 코드와 테스트의 비어 있지 않은 줄 수를 분리하고 도우미를 포함한 전체 Python 파일·분기 노드·import를 집계한다. 줄 수나 분기 노드는 유지보수성 점수가 아니다. 각 조건 한 번씩의 작은 시험이므로 우월성·절감률·모든 작업의 성능을 일반화하지 않는다. 세션 시간·토큰은 관측값이며 앱 실행 속도·메모리 벤치마크가 아니다. 양쪽이 같은 결과면 추가 효과가 입증되지 않았다고 기록한다.

원시 trace·개인 경로·설치 상태·백업은 공개하지 않는다. 검토한 요약과 실패/재시험 기록만 `evals/results/`에 공개한다.

**추가 생산 코드 절감 효과는 관측되지 않았다.** 기존 지침도 충분히 단순한 구현을 만들었다. 추가 테스트의 비어 있지 않은 줄 수는 전체 기존 테스트를 포함해 전/후 각각 CSV 103/91, 집계 142/102, 날짜 126/114였다. 이는 표본의 차이이며 테스트 검증력이 같거나 보강안이 우수하다는 증거는 아니다. 기능 보존과 범위 준수를 확인한 작은 명시 실행 비교이며 운영 앱·UI 접근성·속도·메모리 성능 시험이나 자동 스킬 선택 검증은 아니다.

## 최초 실행의 판정기 보정

Windows에서 CRLF 원본을 텍스트 모드로 다시 쓴 일부 스냅샷에 CRCRLF가 생겼다. 전체 지침이 성공한 명령 출력에 있었지만 기존 정규화가 이를 다르게 처리해 보강 조건의 읽기 판정이 실패했다. 원시 로그와 최초 판정을 보존하고, CR과 이로 인해 늘어난 빈 줄만 정규화한 판정기로 같은 로그를 다시 검사한다. 비어 있지 않은 모든 줄의 본문·들여쓰기·순서를 보존하고, 본문 누락·순서 변경·실패한 읽기가 계속 거절되는 회귀 시험도 포함한다. 모델을 성공할 때까지 재실행하거나 기능 검사를 완화하는 보정이 아니다. 이후 스냅샷은 LF로 기록한다.

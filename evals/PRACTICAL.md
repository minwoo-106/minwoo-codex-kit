# 실제 결과물 평가

선택 평가는 자연어로 알맞은 스킬을 찾는지 확인한다. 실행 평가는 해당 스킬을 명시하고 실제 결과물을 검사한다. 결과를 섞지 않는다.

## 실행 도구 자체의 정상/결함 시험

```text
python -B evals/verify_practical.py --runtime <kit 런타임> --browser <Chrome/Edge> --out <새 폴더>
```

합성 검색 페이지를 실제 브라우저로 조작한다. API 계약, 실제 생성한 1초 MP4·SRT, 메모리 DB의 변경/복구도 검사한다. 정상 4개와 의도적인 결함 4개, 총 8개를 통과해야 한다. 잘못된 앱의 실패가 이 평가에서는 올바른 결함 탐지 결과다. 이 시험은 모델을 호출하지 않아 CI에서도 수행할 수 있다.

## 새 Codex 세션의 실제 작업

```text
python -B evals/run_tasks.py
python -B evals/run_tasks.py --run --runtime <kit 런타임> --browser <Chrome/Edge> --out <새 개인 폴더>
```

현재 로그인·기본 모델로 브라우저/API/영상/DB/CI 다섯 세션을 실행한다. 사용자 설정을 수정하지 않으며 workspace-write는 해당 시험 세션에만 적용한다. 스킬 이름은 명시하므로 이 결과를 자동 선택 정확도라고 부르지 않는다. 실패 사례만 다시 실행하려면 --case 이름을 사용하고 다른 출력 폴더를 지정한다.

평가기는 성공한 문서 읽기, 해당 실행 도구의 명령 기록, 원본 보존, 실제 JSON·스크린샷·trace를 검사한다. CI 사례는 의도적으로 실패하는 합성 로그·Python 함수를 고치고, 공개한 테스트와 별도의 분수·음수 입력으로 수정을 검증한다. 원격 CI 통과를 가장하지 않는다. 문장이나 도구 이름 언급만으로는 통과하지 않는다.

원시 로그·브라우저 trace에는 개인 경로가 있을 수 있으므로 공개하지 않는다. 검토한 summary.json만 배포한다. 실제 OS·브라우저·네트워크 권한에 따라 실행이 실패할 수 있고, 그때는 실패 항목을 남긴다. 예산·시간을 무한히 써서 성공할 때까지 재시도하지 않는다.

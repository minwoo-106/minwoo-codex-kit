# 구현·검증 스킬 실전 평가

```text
python -B evals/run_engineering_tasks.py
python -B evals/run_engineering_tasks.py --run --out <새 폴더> --case state
```

기본은 계획 출력이며 --run은 현재 로그인·기본 모델 사용량을 쓴다. 모델·승인 설정을 저장하지 않는다. Python 3.10+, Node.js와 npm이 PATH에 있어야 한다. npm은 기존 로컬 런타임을 사용할 수 있고 별도 전역 설치는 필요 없다. upgrade는 직접 생성한 로컬 패키지 1.0.0/2.0.0만 오프라인 설치한다.

10개 사례는 테스트 검증력, 실제 패키지 이전, 계측, DB 내부 멱등 작업, 상태 흐름, CSV 재개, Intl 포맷, HTTP 계약, 순서 의존 실패, 동작 보존 정리다. 자연어 자동 선택과 별도로 스킬을 명시한 실제 구현 시험이다.

모델에는 fixture와 공개 요구사항만 제공한다. 상위 평가기의 acceptance 코드는 읽지 않도록 요청하고 모델 종료 후 별도 Python 프로세스에서 검사한다. 이것은 별도 권한 경계를 만든 것이 아니므로 실행 기록도 확인한다. 전체 스킬·필요 참조 읽기, 입력 보존, 정상 종료, 외부 도구 미사용을 함께 검사한다. 합성 프로젝트의 구현·테스트 수정은 해당 요구 범위에서 허용된다.

- quality: 정상 구현 통과와 별도 주입한 세 결함 탐지. 전체 Stryker 시험/변이 점수는 아니다.
- upgrade: 실제 로컬 npm 잠금 기반 재설치와 새 API 호출. 공개 registry 패키지 이전의 일반적 성공 보장은 아니다.
- observability: 시간·결과·예외·민감 필드 제외·sink 실패. 외부 OpenTelemetry 수집기는 시험하지 않는다.
- async: SQLite 중복·동시 호출·재시도·취소. 실제 큐·다중 프로세스 crash·외부 부작용은 미검증이다.
- state: 순수 전이·취소·늦은 응답. 화면 렌더·브라우저 통합은 미검증이다.
- data: 실제 CSV/SQLite·여러 줄 셀·부분 실패·재개·입력 변경·1만 행의 제한된 읽기. 대용량 성능·파일 업로드 서버는 미검증이다.
- i18n: 실제 Node Intl 복수형·fallback·시간대 날짜 경계·통화. 번역 품질·RTL 화면은 미검증이다.
- contract: 실제 로컬 HTTP 제공자와 기존 소비자, 추가/필수 필드 변화. Pact/Broker 시험은 아니다.
- flaky: 공유 기본 목록의 실패 재현과 두 순서 실행. 모든 비결정적 원인 제거를 증명하지 않는다.
- refactor: 정상·경계·잘못된 입력 36개의 값/예외 비교와 실제 코드 변경.

원시 로그·개인 경로·설정·설치 파일은 공개하지 않는다. 검수한 요약만 results에 기록하며 최초 실패도 보존한다. 재시험은 새 폴더에서 필요한 사례만 실행한다. 시간·입출력 한도를 유지하고 평가 기대값을 결과에 맞춰 약화하지 않는다.

# 검증 기록

검증일: 2026-10-29. 최신 대상: 0.5.0. 아래 이전 버전 기록도 보존한다.

## 0.5.0 실행 도구·실제 작업 검증

- 최초 GitHub Actions의 Windows·macOS·Linux 기본 검사는 통과했으나 Linux 실전 검사 준비 중 GNU/musl 영상 도구가 함께 설치되어 단일 파일을 요구하던 탐색이 실패했다. 고정된 Remotion 버전의 운영체제·libc 선택 기능을 사용하도록 수정했고 로컬 실전 8개를 다시 통과했다. 검사 기대값이나 실패 판정은 변경하지 않았다.
- 기존과 역할이 겹친 CI·영상 납품·DB 변경 연습·목록 점검은 기존 스킬을 확장했다. 새 스킬은 브라우저 동작과 API 호환성 2개이며, 기존 diagnosing-bugs를 관리 대상으로 편입해 배포 목록은 17개다.
- 로컬 unittest **78개 중 77개 통과, 1개 생략**. 기존 Windows PowerShell 5.1 실행 정책을 변경하지 않았다. API 입력/응답 방향 차이, 미지원 변경의 review 판정, 영상 규격·자막 범위, 목록 중복/명시 호출/읽기 전용 동작을 검증했다.
- [실제 도구 정상·결함 8개](../evals/results/2026-10-29-tools-050.json) 통과. Edge의 검색 DOM 결과·실패 스크린샷/trace, 실제 생성한 MP4의 ffprobe와 SRT 검사, API 변경 3건, PGlite 데이터 보존·복구 및 데이터 변조 실패를 확인했다. 기술 검사이며 실제 사용자 서비스·청취·영상 화질·운영 DB 동시성을 검증한 것은 아니다.
- [새 Codex 작업 첫 실행](../evals/results/2026-10-29-tasks-050-first.json)은 **4/5 통과**. 5개 모두 결과물 검사는 통과했으나 영상 사례는 성공 코드의 전체 문서 읽기 증거가 없었다. 문서는 읽었지만 같은 셸 명령의 Git 상태 확인이 비저장소 폴더에서 실패했다. 평가 폴더를 빈 Git 저장소로 준비한 뒤 판정 기준·스킬·업무 요청을 그대로 두고 [영상만 재시험](../evals/results/2026-10-29-tasks-050-retry.json)하여 **1/1 통과**했다. 최초 실패 로그는 보존한다.
- 실제 작업 평가는 스킬을 명시한다. 별도 [자연어 선택 시험 12개](../evals/results/2026-10-29-selection-050-targeted.json)는 스킬 이름을 알려주지 않고 모두 통과했다. 실제 실행·선택 정확도를 혼동하지 않는다.
- [기존 요청 15개 회귀 시험](../evals/results/2026-10-29-selection-050-regression.json)은 14/15 통과했다. 일반 영상 비교가 특정 스튜디오 전용 스킬로 잘못 선택되는 실제 충돌을 발견했다. 일반 프로젝트의 두 영상·같은 컷·반복 비교라는 발동 설명을 명확히 하고 [비교·납품·렌더 3개를 재시험](../evals/results/2026-10-29-selection-050-video-retry.json)해 3/3 통과했다. 합계 27개 요청을 다뤘으며 첫 실행 26/27과 수정 후 결과를 구분한다. 미래의 모든 요청에 대한 완전한 선택 정확도를 보장하지 않는다.
- [목록 크기](../evals/results/2026-10-29-inventory-050.json): 지정한 사용자·활성 플러그인 경로의 파일 93개, 자동 선택 후보 87개, 명시 호출 전용 6개, 중복 이름 없음. 전체 발견 목록 재구성은 36,448자/38,892바이트, 그중 kit 17개는 3,293자/5,354바이트이며 kit 설명 최대 156자다. 개인 경로·전체 스킬 목록은 공개하지 않는다.
- 전체 목록은 모델 문맥 미확인 시의 8,000자 비교선을 넘는다. 실제 모델 문맥 크기와 skills.max_context_tokens는 로컬 설정에 명시되지 않아 실제 초과·잘림·누락이나 정확한 토큰 수를 단정하지 않았다. 플러그인 설명·선택 정책·승인 설정은 변경하지 않았다.
- Playwright 1.62.1을 고정한 새 별도 런타임을 설치했고 npm audit 조회 결과 0건이다. 브라우저는 기존 Edge를 재사용했으며 원래 런타임·프로젝트 의존성·PATH는 유지했다.
- 설치 후 17개 관리 스킬이 원본과 일치하고 설치 미리보기의 변경 예정은 0개다. 시작 시 보호한 470개 기존 파일 중 의도한 스킬 본문 4개를 바꿨다. 전역 AGENTS.md를 포함한 465개는 해시가 유지됐다. config.toml 한 파일은 작업 도중 별도 변경이 감지됐으며 변경 주체와 내용 차이는 이전 본문 사본이 없어 확정하지 못했다. 이 작업의 도구는 승인 설정을 쓰지 않았고 해당 파일을 덮어쓰거나 되돌리지 않았다. 확인 시 명시적 approval_policy/approvals_reviewer/sandbox_mode 설정은 없었다. 현재 실행 환경은 기존 대신 승인 방식을 유지한다.

## 0.4.0 운영·선택 평가 검증

- 실제 Codex CLI 0.165.0-alpha.1.2, 현재 사용자의 기본 모델·설치 스킬 목록으로 새 읽기 전용 세션을 실행했다. 스킬 이름을 알려주지 않은 요청 14개, kit 제외 요청 6개, 복합 요청 1개를 사용했다.
- [첫 실행](../evals/results/2026-10-29-first.json)은 **20/21 통과**. PostgreSQL 사례는 전체 문서를 읽었지만 같은 명령의 없는 파일 확인이 종료 코드 1을 반환했다. 실패한 명령을 증거로 인정하지 않는 기존 판정을 유지했다. 프롬프트·스킬·판정 기준을 바꾸지 않고 해당 사례만 [재시험](../evals/results/2026-10-29-retry.json)하여 **1/1 통과**했다. 첫 실패도 보존한다. 제외 요청 6개에서 kit 스킬 오발동 없음, 복합 요청에서 React 스킬 2개 선택을 확인했다.
- 이 평가는 읽기 전용 준비 요청에서의 선택 확인이다. 전체 작업 수행 성공이나 미래 요청의 100% 정확도를 주장하지 않는다. 원시 실행 로그는 개인 경로가 포함될 수 있어 로컬에만 보존했다.
- Windows 로컬 unittest **70개 중 69개 통과, 1개 생략**. 기존 PowerShell 5.1 실행 정책은 변경하지 않았다. Python/PowerShell 7/Git Bash 진입점, 설치 묶음 중복·반복·규칙 보존, 없는 환경 doctor 무쓰기, 중복·캐시·미완료 런타임 분류, 커밋만 압축·해시·잘못된 태그·민감 파일 거절, 평가 증거 위조·실패 명령·과도한 스킬·외부 작업 판정, OSV 불완전 응답 거절을 확인했다.
- 초기 제한 환경에서 로컬 소켓/Git Bash 테스트가 차단되어 정상 권한의 격리 테스트 폴더에서 재검증했다. 압축 테스트의 Windows 줄끝 가정도 실제 커밋 바이트와 비교하도록 수정했다. 실패를 생략하거나 승인 설정을 변경해 통과시킨 것이 아니다.
- 이 PC의 미설치 기본 스킬 2개와 유지보수 비교 도구 개선을 반영했다. 설치된 kit **14개 모두 원본과 일치**, 중복·doctor 경고 없음, 기존 선택 실행 도구 상태 ready. 점검 시작 전 468개 파일 중 의도한 유지보수 도구 한 파일만 변경되었고 **나머지 467개(전역 AGENTS.md·config.toml 포함)는 해시가 유지**되었다. 전역 규칙과 배포 원본의 기존 차이는 보존했다.
- GitHub에서 여러 OS와 실행 도구를 검사하는 워크플로를 추가했다. 실제 실행 결과는 해당 커밋의 [Actions](https://github.com/minwoo-106/minwoo-codex-kit/actions)에서 확인한다. 로컬 Windows 결과를 다른 OS 실행 증거로 대신하지 않는다.
- 첫 GitHub 실행에서 Windows·Linux 두 Python 버전·선택 도구 작업은 통과했다. macOS에서 선택 도구 테스트 두 개가 지정된 임시 폴더를 사용하지 않아 `/var` 시스템 링크 거절에 걸렸다. 다른 테스트와 같은 `KIT_TEST_ROOT`를 사용하도록 수정했으며 링크 거절 규칙은 유지했다. 실제 ZIP 생성에서 발견한 형제 폴더 상대 경로 처리도 수정하고 회귀 사례를 추가했다. 최종 테스트 수는 71개다.

## 0.3.0 후보 검수·도구·설치 검증

- kit unittest **59개 중 58개 통과, 1개 생략**. Windows PowerShell 5.1의 기존 실행 정책 때문에 실행 검증만 생략했으며 정책을 바꾸지 않았다.
- 의존성 감사 원본 pytest **105개 통과**. POSIX getuid 분기를 Windows에서도 명시적으로 모사하도록 테스트를 보완했고, Windows 소유자 검증 한계 경고도 확인했다. 최종 pytest 9.2.0에서 재검증했다.
- 14개 SKILL.md의 공식 quick_validate 통과. 8개 추가분의 발동/제외 범위를 기존 UI·TDD·디버깅·영상 검토·인수인계와 수동 대조했다.
- 공개 fast-check 4.10.2 한 개를 실제 조회해 JSON·Markdown 보고서를 생성했다. 직접 의존성 1개, 13개 기준 중 게시자 집중도 1개 미확인, lockfile이 없어 전이 의존성 미검사임을 보고서에 표시했다. 회사·사용자 프로젝트를 조회하지 않았다.
- 변경 설명: 원본 패치 대조, 가짜 diff·존재하지 않는 줄 거절, 실제 Edge에서 단계 이동·리뷰 줄 연결·외부 HTML 제거 확인. 페이지 오류·외부 요청 없음.
- fast-check/Hypothesis: 잘못된 왕복 함수를 실패시키고, 올바른 왕복을 각각 500회 검증. Hypothesis는 반례를 [0]으로 축소했다.
- React: context 기반 합성의 서버 렌더 결과, 독립 요청의 동시 시작 예제 확인. 실제 사용자 앱의 성능 개선을 측정한 것은 아니다.
- PGlite: 테이블·인덱스·조회·실행 계획과 비소유자 역할의 RLS 허용/차단 확인. 운영 PostgreSQL, 동시성, Supabase 인증 서비스까지 확인한 것은 아니다.
- Remotion: 한글 SRT 시간 파싱, 실제 MP4 생성(640×360, 30fps, 2초), 자막 전/첫 자막/두 번째 자막 프레임 생성. 첫·두 번째 한글 자막의 실제 화면을 확인했다. 샘플은 무음으로 실제 음원 동기화 검증은 제외한다.
- Node 잠금 파일 npm audit 0건. Python 고정 패키지 9개 OSV 조회 0건. 발견된 Zod·pytest·Pygments 후보 취약 버전은 교체하고 대표 실행/테스트를 다시 수행했다. 재조회 시 결과가 달라질 수 있다.
- 선택 도구 설치: 공식 npm SHA-512, Node 잠금 파일, Python wheel 해시 사용. 압축 경로 이탈·링크·해시 불일치 거절, 미리보기 무쓰기, 미관리/수정 폴더 거절 확인.
- 실제 PC에 새 스킬 8개, 배포 자원 **149개 파일**과 별도 실행 도구를 설치했다. 설치 직후 기존 규칙·설정·스킬 319개 파일의 해시가 유지되었다. 최종 대조에서는 전역 규칙·기존 스킬 318개가 그대로였고, config.toml만 중간에 변경되었다. 설치기에는 이 파일을 쓰는 경로가 없으며 변경 주체는 확인하지 못했다. 해당 파일을 되돌리지 않았다. 새 설치본과 원본의 바이트 일치, 같은 버전 재설치 시 파일 수정 시각 불변을 확인했다.
- 테스트 캐시·node_modules가 스킬 설치에 섞이지 않도록 제외 규칙과 회귀 테스트를 추가했다. 원본 문서의 코드/빈 줄 줄끝 공백 15개 파일을 정리하고 변경 이력을 기록했다.

개인 설치 경로·상태·백업·캐시·원시 검사 보고서는 공개 저장소에 넣지 않았다. 임시 시험용 PC 런타임을 최종 수정 버전으로 대체했다.
실제 실행 환경은 Windows, Python 3.11, Node 24, Edge다. 네이티브 Linux/macOS 실행과 새 Codex 대화의 자동 스킬 선택은 검증하지 않았다.
실행 도구·SQL·React 참고 규칙이 모든 프로젝트에서 자동으로 맞는다고 보장하지 않으며 프로젝트 버전과 실제 요구에 맞춰 선택한다.

- 브라우저에서 영상 길이를 넘는 컷의 재생 차단, 실행 중 영상 변경 후 요청·메모 검증 거절 확인. 페이지 JavaScript 오류 없음.
- 1280px 및 390px 폭의 화면 캡처를 확인했고 모바일 가로 넘침이 없었다. 샘플 영상은 무음으로, 실제 청취 검증은 하지 않았다.
- 여섯 SKILL.md의 quick_validate 검사와 스킬 내부 참고 링크 확인 통과. 새 Python 도구는 3.10 문법 검사 통과, 실제 실행은 3.11.

첫 제한 환경 실행에서는 로컬 소켓 연결이 차단되었다. 이후 허용된 실행 환경에서 위 서버·브라우저·설치 테스트를 수행했다.
Playwright는 브라우저 검증에만 사용하며 배포 도구의 실행 의존성이 아니다. 외부 프로젝트 코드·실제 영상·인증 자료는 사용하지 않았다.

스킬의 발동 범위와 인수인계·검수 절차를 수동 검토했다. 독립된 모델 평가나 새 대화에서 자동 선택되는지의 행동 평가는 수행하지 않았다.
네이티브 Linux·macOS, 모든 영상 코덱, 프레임 단위 동기화는 검증 범위에 포함하지 않는다.

## 추가 확인

- 제공된 전역 AGENTS.md와 비교: 삭제한 문장 0개, 추가한 문장 2개. 기존 11개 영역 보존.
- 두 스킬 모두 제공된 skill-creator의 `quick_validate.py` 검사 통과. 검사에만 필요한 PyYAML은 배포본 밖의 작업 폴더에서 사용했다. 설치기에는 외부 Python 패키지가 필요 없다.
- 두 스킬의 설명과 절차를 수동 검토해 발동 범위를 구분했다. 실제 Codex 모델의 자동 선택에 대한 별도 행동 평가는 수행하지 않았다.
- Python 3.10 문법으로 구문 분석 통과. 실제 실행은 Python 3.11에서 수행했다.
- 현재 배포 파일의 로컬 사용자 경로·주요 토큰 형태·개인키 본문 패턴을 점검했고 발견 사항은 없었다. 직접 작성한 파일과 사용자가 제공한 일반 규칙 외의 회사 자료·기존 스킬은 가져오지 않았다.
- 위 검증은 최초 게시 전에 수행했다. 공개 대상은 이번에 작성한 파일들이며 이전 Git 이력은 없었다.

## 확인하지 않은 범위

Windows PowerShell 5.1 실행 정책을 변경하지 않았다. 해당 환경에서는 README의 Python 진입점을 사용할 수 있다.

비밀정보 패턴 검사와 수동 검토는 모든 민감정보의 부재를 보장하지 않는다.

사용자 요청으로 전역 원본에 ‘개인 Codex kit 참고’ 영역을 추가하고 README·설계 설명을 갱신했다.

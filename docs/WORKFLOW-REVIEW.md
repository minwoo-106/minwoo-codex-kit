## 기존 디버깅 스킬 편입

[원본](https://github.com/mattpocock/skills/tree/59db609eb1e18aaf59b63284d0e52255aff0c63c/skills/engineering/diagnosing-bugs)과 MIT 라이선스를 확인했다. 현재 PC의 CONTEXT.md 참조를 보존했으며 원본 커밋의 GLOSSARY.md 참조로 되돌리지 않았다. 같은 이름의 두 번째 스킬을 만들지 않고 같은 폴더를 관리 대상으로 편입했다. 새 CI 문서를 읽는 링크 외에는 기존 본문·템플릿·UI 메타데이터를 보존한다. [변경 이력](../skills/diagnosing-bugs/UPSTREAM.md).

다른 PC에 이미 diagnosing-bugs가 있고 내용이 다르면 설치기는 충돌로 멈춘다. 그 차이를 확인·병합한 뒤 해당 스킬만 명시적으로 교체한다. all 묶음 설치에 무조건 --replace-existing을 붙이지 않는다.

## 도구·공개 범위

- 새 Python 도구는 표준 라이브러리로 실행된다. PGlite와 ffprobe는 기존 고정 Remotion/DB 도구를 재사용한다.
- Playwright는 기존 선택 런타임에 고정 의존성으로 추가했다. 기존 런타임·프로젝트 의존성·전역 PATH는 유지한다. 새 PC의 브라우저 설치 여부는 별도 확인한다.
- GitHub CI는 격리 runner에 Chromium을 설치하고 실제 브라우저·영상·DB 사례를 실행한다. 실제 모델 호출은 명시적으로 실행하는 로컬 평가만 수행한다.
- 모델 실행 원시 로그·실제 PC 경로·전체 설치 목록·합성 영상 바이너리는 저장소에 넣지 않는다. 합성 입력 생성기와 검토한 요약만 배포한다.
- 기존 승인 방식, 전역 AGENTS.md, 모델 설정과 다른 플러그인 캐시는 바꾸지 않는다.

## 목록 크기 해석

문자 수와 바이트 수는 실제 모델 토큰 수가 아니다. 공식 설명의 8,000자 대체 기준과 비교할 수 있으나 실제 모델 문맥 크기를 알지 못하면 실제 잘림/누락 여부를 단정하지 않는다. 전역 캐시 전체가 아니라 현재 세션에 제공된 활성 플러그인 경로와 사용자 스킬을 조사한다. 모델의 실제 노출 집합은 별도 사실이며 선택 시험 성공도 모든 스킬 노출을 증명하지 않는다.

새 스킬은 짧은 발동 설명을 두고 상세 작업을 참고 자료에 배치했다. 불필요한 공통 승인 절차나 항상 실행하는 검사를 추가하지 않았다.

묶음은 설치할 파일의 선택이다. 이미 설치된 다른 스킬을 삭제하거나 비활성화하지 않는다.
일반 작업에는 스킬 이름·설명으로 필요한 것을 고르고, 선택한 본문과 필요한 참고 자료만 읽는다.
설치했다고 모든 스킬의 본문이나 규칙을 한 번에 적용하지 않는다. 모델의 선택은 확률적이므로 평가 결과가 모든 미래 요청을 보장하지는 않는다.

```powershell
# 목록 조회는 아무것도 설치하지 않는다.
.\scripts\install.ps1 -ListProfiles
# 기존 공통 규칙은 보존하고 선택 스킬만 설치한다.
.\scripts\install.ps1 -Profiles all -SkipRules -DryRun
.\scripts\install.ps1 -Profiles all -SkipRules
```

```sh
sh scripts/install.sh --profile web --skip-rules --dry-run
sh scripts/install.sh --profile web --skip-rules
```

기본 스킬 경로는 `~/.agents/skills`다. 기존 PC가 `~/.codex/skills`를 쓰면 PowerShell의 `-SkillsRoot`, Python/Unix의 `--skills-root`로 기존 경로를 지정한다. 둘에 중복 설치하지 않는다. 여러 `--profile`과 `--skill`은 합집합으로 처리한다. 프로필이 없을 때 기존 설치 동작은 그대로다.

## 읽기 전용 상태 점검

```sh
python -B scripts/doctor.py --profile all --json
```

규칙·스킬 원본과 설치본 차이, 중복, Git/Node/Python, Codex 실행 파일 위치 확인, 브라우저 존재, 별도 실행 도구의 설치 기록·필수 파일을 확인한다. 개인 절대 경로·설정 내용·인증 자료는 출력하지 않는다. 파일과 설정을 수정하거나 인터넷에 접속하지 않는다.

`same`, `missing`, `different`, `duplicate`로 스킬 상태를 구분한다. 규칙의 차이는 사용자 선호일 수 있으므로 오류나 자동 덮어쓰기 대상으로 취급하지 않는다. 경고가 있어도 점검을 정상 완료하면 종료 코드 0, 경로·형식 문제로 점검을 완료하지 못하면 1이다. 브라우저의 실제 렌더, 모든 실행 도구의 내부 파일 무결성, 플러그인의 계정 연결·서비스 권한은 이 점검만으로 확인되지 않는다.

## GitHub 검증과 의존성 갱신

- main 푸시·PR·버전 태그: Windows/macOS/Linux 설치·반복·충돌·복구 테스트, 스킬 메타데이터·문서 링크·프로필·평가 사례·고정 의존성 검사.
- 별도 Linux 작업: 선택 도구 격리 설치, Node/Python 알려진 취약점 조회, 대표 실행 예제, 의존성 감사 도구 회귀 테스트.
- 스킬 선택의 실제 모델 평가는 계정 사용량이 발생하므로 로컬에서 명시적으로 실행한다. CI는 평가 판정 로직과 사례 구조를 검사하며 실제 모델 평가를 대신하지 않는다.
- Dependabot은 매주 월요일 오전 9시(한국 시간)에 Node/Python/Actions 갱신 PR을 제안한다. 각 종류별 열린 PR은 최대 2개. 자동 병합·이 PC의 자동 갱신은 없다.
- PR을 검수하고 검사 통과 후 반영한다. 설치 도구·해시 잠금·출처 기록이 연동되므로 의존성 PR만 통과했다고 모든 배포 준비가 끝난 것은 아니다. 복사한 참고 문서의 새 버전은 유지보수 작업에서 별도 검수한다.

공개 전 검사는 흔한 인증정보 패턴·개인 경로·생성 파일을 탐지하는 보조 검사다. 모든 민감정보 탐지를 보장하지 않으며 실제 변경 내용 검토도 함께 수행한다. GitHub의 저장소 설정을 통한 필수 검사 강제·브랜치 보호까지 설정한 것은 아니다.

## 버전 ZIP과 복구

`VERSION`과 일치하는 `vX.Y.Z` 태그를 올리면 해당 커밋의 검사를 모두 통과한 뒤 ZIP, `release.json`, `SHA256SUMS`를 GitHub Release로 공개한다. 기존 릴리스는 덮어쓰지 않는다. 배포에는 커밋된 파일만 포함하며 이 PC의 인증·설정·설치 상태·백업·평가 원시 로그는 포함하지 않는다.

로컬에서 커밋 기반 묶음을 만들려면 저장소 밖의 새 출력 폴더를 지정한다.

```sh
python -B scripts/build_release.py --output ../kit-release --tag v0.10.0
```

다운로드 후 `SHA256SUMS`의 ZIP 해시와 `Get-FileHash -Algorithm SHA256 파일.zip` 또는 `sha256sum 파일.zip` 결과를 대조한다. 해시는 파일 손상 검사용이며 별도 서명이나 신원 증명은 아니다. 압축을 새 폴더에 풀고 미리보기부터 실행한다.

문제가 생기면 자동 업데이트를 반복하지 말고 현재 수정 파일을 먼저 보존한다. 설치 시 기록한 `.minwoo-codex-kit/backups/<실행 식별자>/restore-map.json`에서 대상 파일과 `.bak`의 대응을 확인하고 원하는 파일만 비교·복구한다. 백업 파일·대상 경로가 예상한 로컬 파일인지도 확인한다. 설정 파일은 kit 설치 대상이 아니므로 통째로 되돌리지 않는다.

이전 버전으로 돌아갈 때는 해당 Release ZIP을 별도 폴더에 풀어 설치 미리보기를 확인한다. 로컬 수정 충돌은 먼저 비교하며 `--replace-existing`을 기본 갱신 절차에 넣지 않는다. 새 버전에서 추가된 스킬은 옛 버전 설치만으로 자동 삭제되지 않는다. 선택 실행 도구도 내용별 별도 폴더이므로 이전 런타임을 보존한다. 실행 도구 내부 경로나 인증 정보를 공용 문서에 복사하지 않는다.

설치기 백업은 파일 복구 수단이고 GitHub Release는 검수한 원본 복원 수단이다. 둘 다 사용자 프로젝트 전체의 백업을 대신하지 않는다.
